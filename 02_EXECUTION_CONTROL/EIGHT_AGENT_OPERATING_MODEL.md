# Link168 八 Agent 固定运行模型

## 1. 决策

Link168 固定使用八个开发 Agent。八个 Agent 是岗位，不是临时提示词；名称、编号和职责不得自行增加、拆分、合并或改名。

| 编号 | 唯一正式名称 | 核心责任 |
|---|---|---|
| 01 | 总控架构与集成 Agent | 拆任务、定边界、排共享文件、集成与裁决升级 |
| 02 | 产品规则与需求治理 Agent | 宪法/PRD一致性、业务规则、状态与验收口径 |
| 03 | 身份权限与企业空间 Agent | 登录、会话、身份绑定、角色、租户和企业成员生命周期 |
| 04 | 商业主页与前端体验 Agent | 官网、后台体验、名片编辑、组件、预览、公开页和移动端 |
| 05 | 客户线索与访问分析 Agent | 留资、客户、跟进、访问事件、归因、报表和隐私展示 |
| 06 | AI接待与知识库 Agent | 阿里云百炼、访客AI接待、六大AI Agent、知识库、调用记录与安全降级 |
| 07 | 会员支付与平台治理 Agent | 套餐权益、AI额度、支付宝订单退款、推广结算、Jeepwork平台治理 |
| 08 | 质量安全与发布 Agent | 测试、安全、构建、发布检查、回滚证据和Showcase保护性验证 |

## 2. 指挥关系

```text
老板：产品方向、价格、权益、删除、生产和外部系统最终批准
  ↓
Agent 01：任务编排、文件授权、冲突处理和集成
  ↓
Agent 02–07：按业务域开发
  ↓
Agent 08：独立验收，不替业务 Agent 宣布通过
```

Agent 01 不是老板代理人，无权改变产品定位、价格、权益、删除政策或生产架构。Agent 08 有权因证据不足驳回验收，但无权重写产品规则。

## 3. 并发规则

1. 并发按业务域，而不是按页面数量。
2. 两个 Agent 需要修改同一文件时，不得并发；Agent 01 指定唯一写入者和顺序。
3. `prisma/schema.prisma`、migration、`package.json`、锁文件、根布局、全局中间件、公共权限入口和正式文档均属于共享高风险范围。
4. 数据库迁移一次只能有一个负责人，并需老板明确批准数据库变更。
5. Agent 08 可与开发并行编写独立测试，但不得同时修改开发 Agent 正在编辑的业务文件。
6. 没有任务卡、文件清单和验收方式，不得开始写代码。

## 4. 固定工作流

```text
老板确认本轮目标
→ Agent 02 固化规则与验收口径
→ Agent 01 分配任务卡和文件所有权
→ Agent 03–07 在无冲突域内并发开发
→ Agent 01 集成并解决共享文件
→ Agent 08 独立验收
→ 老板批准涉及上线、外部系统或生产的下一步
```

## 5. 全员硬边界

- 禁止修改 `00_GOVERNANCE_LOCKED/**`；只能提交变更建议，由老板批准。
- 禁止自行删除页面、路由、模型、字段、会员、AI、支付、企业或未来结构。
- 禁止触碰生产服务器、生产数据库、密钥、支付宝、阿里云邮件推送或阿里云百炼真实配置，除非老板单独授权。
- 禁止创建第九个开发 Agent；临时审计可以作为任务，但必须归属八个岗位之一。
- 禁止跨域“顺手修复”；发现问题写入交接清单。
- 禁止把 Mock、Demo、占位或未配置调用标记为生产可用。
- 每次执行必须写入自己的 `05_OPERATION_LOGS/agent-XX/`，不得改写他人日志。

## 6. Showcase 特别规则

- `/showcase`、比赛展示页面、对应路由和规则永久保留。
- 正常构建和上传服务器时必须包含，不得从部署包中排除。
- 当前状态为“暂不更新”，Agent 03–07 均不得修改其内容和功能。
- Agent 08 只负责路由存在、构建包含、无普通首页入口及权限/隐私规则的保护性验证。
- 任何恢复更新或产品调整必须由老板明确批准并重新分配负责人。
