## 2. P0 路线 — 7月1日内测版发布前必须完成

|---|------|------|---------|

| P0-3 | 生成 1 个演示账号与 5 条链接 | 方便比赛现场演示和录屏 | — |

| P0-5 | 关键页面截图（至少 8 张） | 首页 / 注册 / 登录 / Dashboard / 公开主页 / 举报 / 管理员后台 / 移动端 | `docs/screenshots/`（自行创建） |

## 3. P1 路线 — 内测版发布前后高质量加分

> P1：对产品真实感、内测用户体验有明显提升，但不满足也不影响 P0 的完成

| # | 任务 | 说明 |
|---|------|------|
| P1-1 | 补齐真实 SMTP 邮件发送链路 | 让"忘记密码 / 邮箱验证"真能收到邮件 |
| P1-2 | 完善二维码生成 → 展示 → 下载 → 扫码的闭环 | 让"二维码营销"卖点有实物 |
| P1-3 | 完善举报状态流转（待处理 / 已处理 / 已驳回） | 管理员后台从"能查看"升级为"能处理" |
| P1-4 | 公开主页 OG / SEO 标签 | 分享时预览更漂亮 |
| P1-5 | 移动端多机型自测 | 长列表、输入框、软键盘遮挡等问题 |
| P1-6 | 超级管理员后台第一版原型 | 参考 `docs/SUPER_ADMIN_PRD.md` |
| P1-7 | 轻量点击数据采集 MVP | 只采集必要字段，合规优先 |
| P1-8 | Pro 会员方案文档 | 定义功能清单、价格、展示形式（UI 暂不写代码） |

## 4. P2 路线 — 后续规划

> P2：比赛后继续演进的方向，目前只写方向不写死日期

| # | 任务 | 方向 |
|---|------|------|

| P2-10 | 企业 AI（需接入真实 AI 服务并合规评审） | 需谨慎推进 |

## 6. 风险与缓解

| 风险 | 影响范围 | 缓解方式 |
|------|---------|---------|
| SMTP 无法在比赛前打通 | 忘记密码 / 邮箱验证演示降级 | 演示时跳过 / 使用本地邮箱服务 / 或在演示视频中标注 |
| 管理员完整工作流未实现 | 管理员部分只能演示"查看" | 明确在 PPT 中说明"状态流转为规划功能" |
| PM2 / 线上稳定性 | 不影响比赛（本地演示为主） | 比赛期间不动线上；任何部署由老板确认 |
| 数据统计 / AI / 支付均未实现 | 被评委质询"产品是不是空壳" | 按 `09-COMPETITION_PLAN.md` §12 主动声明，**不夸大** |
| 文档与代码版本不一致 | 可信度扣分 | 每次代码大变更后同步更新 `docs/product/02-PROJECT_STATUS.md` |
