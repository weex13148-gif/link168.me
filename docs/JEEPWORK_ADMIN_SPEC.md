## 1. 文档目标与定位

### 1.1 文档目标

本规范定义 Link168 V2 平台统一控制平面 `/jeepwork` 的：

1. 一级导航与页面归属
2. 平台级对象与企业工作空间对象的边界
3. 每个核心页面的字段、操作、状态与验收标准
4. 高风险操作统一流程与不可抵赖审计要求
5. 角色权限矩阵与敏感数据脱敏规范
6. 系统健康与外部服务状态检查标准

### 1.2 `/jeepwork` 的定位

`/jeepwork` 是 **Link168 平台统一控制平面**，不是普通用户后台，也不是单纯数据大屏。

- **不是**普通用户后台：普通用户使用 `/workbench`、`/dashboard` 等进行经营；`/jeepwork` 不面向普通用户开放
- **不是**单纯数据大屏：`/jeepwork` 是可写控制平面，承载用户治理、会员治理、订单治理、AI 治理、支付治理、安全审计、生产运维等高权限操作
- **不是**企业管理员后台：企业管理员在 `/workbench/enterprise` 等入口治理本企业工作空间；`/jeepwork` 治理的是跨企业、跨用户的平台级对象

### 1.3 与企业管理员后台的严格隔离原则

| 维度 | `/jeepwork`（平台控制平面） | 企业管理员后台（企业工作空间） |
|------|------------------------------|--------------------------------|
| 登录入口 | `/jeepwork/login` 独立登录 | 普通用户 Session（`link168_session`） |
| Session Cookie | `link168_admin_session` | `link168_session` |
| 认证模块 | `src/lib/jeepwork-auth.ts` | `src/lib/auth.ts` |
| 权限校验 | `requireJeepworkSuperAdmin` / `requireJeepworkAdmin` / `requireJeepworkSessionUser` | 企业成员权限校验 |
| 数据范围 | 全平台（跨企业、跨用户） | 单企业工作空间 |
| 审计要求 | 不可抵赖审计日志（操作人、时间、IP、UA、原因、前后值） | 企业内部审计 |
| 路由前缀 | `/jeepwork/*`、`/api/jeepwork/*` | `/workbench/*`、`/api/workbench/*` |

**禁止**：在企业管理员后台暴露平台级对象（如全平台用户列表、AI Provider 配置、支付对账）；在 `/jeepwork` 直接操作单企业的品牌、模板、产品等企业工作空间对象（必须通过平台级 API 间接治理，且记录完整审计）。

### 1.4 旧 `/admin` 路由状态

旧 `/admin` 路由共 6 个页面，已全部 `notFound()` 返回 404，标记为【历史废弃】。本规范不再展开旧 `/admin` 实现，所有平台治理能力以 `/jeepwork` 为唯一入口。

### 2.3 API 基线

`/api/jeepwork/*` 共 30+ 端点，覆盖：用户、会员、订单、举报、AI 用量、AI 安全、AI Credit、设置（AI / 支付 / API）、内容审核、审计日志、系统健康、Showcase、比赛中心、对账等。

所有 `/api/jeepwork/*` 端点必须满足：

1. 入口处调用 `requireJeepworkSessionUser` / `requireJeepworkAdmin` / `requireJeepworkSuperAdmin` 之一
2. 写操作必须记录不可抵赖审计日志（详见第 6 章）
3. 返回结构统一为 `{ ok: boolean, data?, error?, code? }`
4. 高风险操作必须二次确认 + 原因字段（详见第 6 章）

### 2.4 当前限制（必须如实标注，不得隐瞒）

| 限制项 | 状态 | 影响 |
|--------|------|------|
| AI 成本统计只有 Credit 计数，无按模型单价计算真实成本 | 【部分实现】 | `/jeepwork/ai-cost` 不能反映真实财务支出 |
| 退款只更新本地状态，不调用支付宝退款接口 | 【部分实现】 | 存在用户已支付但平台未实际退款的对账风险 |
| 到期降级无定时任务 | 【部分实现】 | 会员到期后权益不会自动回收，依赖人工触发 |
| 限流基于内存存储，多实例失效 | 【部分实现】 | 多实例部署时限流不生效，存在被刷风险 |

> 上述限制必须在对应页面的"系统降级状态"中显式提示，并在 `/jeepwork/system-health` 的"已知限制"区块集中展示。

## 3. 一级导航统一规划【本次改版】

### 3.1 一级导航分组

`/jeepwork` 一级导航统一收敛为 8 个分组，原有页面按职责归位：

| # | 分组 | 包含路由 | 主要角色 |
|---|------|----------|----------|
| 1 | **总览** | `/jeepwork` | super_admin / admin |
| 2 | **用户与企业** | `/jeepwork/users`、`/jeepwork/users/[id]`、`/jeepwork/profiles`、`/jeepwork/membership` | super_admin / admin |
| 3 | **内容与治理** | `/jeepwork/reports`、`/jeepwork/governance`、`/jeepwork/showcase` | super_admin / admin |
| 4 | **AI 治理** | `/jeepwork/ai-usage`、`/jeepwork/ai-cost`、`/jeepwork/ai-safety`、`/jeepwork/settings/ai`、`/jeepwork/competition-ai-debug` | super_admin / admin |
| 5 | **支付与商业化** | `/jeepwork/orders`、`/jeepwork/settings/payment` | super_admin / admin |
| 6 | **外部展示** | `/jeepwork/showcase`、`/jeepwork/competition-center` | super_admin / admin |
| 7 | **安全与审计** | `/jeepwork/audit`、`/jeepwork/logs`、`/jeepwork/roles` | super_admin |
| 8 | **系统与运维** | `/jeepwork/system-health`、`/jeepwork/settings/api` | super_admin |

> `showcase` 同时归属"内容与治理"和"外部展示"，导航上归入"外部展示"为主入口，"内容与治理"提供治理视角的链接。本次改版后以"外部展示"为唯一一级入口。

### 3.2 导航分组原则

1. **按职责不按技术栈**：分组对应治理职责，不对应 API 模块
2. **角色收敛**：每个分组明确主角色，权限不足时该分组在侧边栏隐藏
3. **跨分组跳转需保留上下文**：从总览跳转至用户详情必须携带来源标记，便于审计回溯
4. **导航顺序固定**：总览 → 用户与企业 → 内容与治理 → AI 治理 → 支付与商业化 → 外部展示 → 安全与审计 → 系统与运维

### 3.3 导航视觉规范

- 当前选中分组高亮，子页面在分组下折叠展示
- 每个分组前使用统一图标集，禁止混用
- 分组标题使用平台主色，禁止使用与普通用户后台相同的视觉风格以强化"控制平面"心智

## 4. 平台级对象 vs 企业工作空间对象

### 4.1 严格隔离原则

`/jeepwork` 只治理 **平台级对象**，不直接操作企业工作空间对象。两者在数据模型、API 路径、权限校验、审计要求上完全隔离。

### 4.2 平台级对象（只允许在 `/jeepwork` 治理）

| # | 对象 | 治理入口 | 说明 |
|---|------|----------|------|
| 1 | 全平台用户 | `/jeepwork/users` | 跨企业、跨角色的所有用户账号 |
| 2 | 全平台企业 | `/jeepwork/users`（企业维度视图） | 平台内所有企业工作空间的总览与冻结 |
| 3 | AI Provider | `/jeepwork/settings/ai` | 通义千问 / OpenAI / 自建等 Provider 配置 |
| 4 | 全平台模型和成本 | `/jeepwork/ai-cost`、`/jeepwork/settings/ai` | 模型清单、单价、Token 上限、Credit 兑换比 |
| 5 | 支付与对账 | `/jeepwork/orders`、`/jeepwork/settings/payment` | 支付宝配置、对账、退款审批 |
| 6 | 系统配置 | `/jeepwork/settings/api`、`/jeepwork/settings/ai`、`/jeepwork/settings/payment` | 平台级开关、密钥、限流 |
| 7 | 举报治理 | `/jeepwork/reports`、`/jeepwork/governance` | 全平台举报、处置、申诉 |
| 8 | 安全审计 | `/jeepwork/audit`、`/jeepwork/logs` | 不可抵赖审计、系统日志 |
| 9 | 生产运维 | `/jeepwork/system-health` | 健康、外部服务、限流、降级 |
| 10 | `/showcase` 全局控制 | `/jeepwork/showcase` | Showcase 开关、密码、模式 |
| 11 | 管理员和权限 | `/jeepwork/roles`、`/jeepwork/governance` | 三级角色、最后一名超管保护 |

### 4.3 企业工作空间对象（不允许在 `/jeepwork` 直接操作）

| # | 对象 | 治理入口 |
|---|------|----------|
| 1 | 本企业成员 | `/workbench/enterprise` |
| 2 | 本企业品牌 | `/workbench/card`、`/dashboard` |
| 3 | 本企业模板 | `/dashboard` |
| 4 | 本企业产品和资料 | `/workbench/products`、`/dashboard` |
| 5 | 本企业 AI 接待 | `/workbench/ai`、`/workbench/ai-service` |
| 6 | 本企业线索 | `/workbench/leads` |
| 7 | 本企业数据 | `/workbench/analytics` |
| 8 | 本企业账单和用量 | `/workbench/membership` |

### 4.4 跨边界操作规则

1. `/jeepwork` 治理平台级对象时，如需联动企业工作空间（如冻结用户导致其企业失主），必须通过平台级 API 间接触发，且在审计日志中记录联动影响
2. `/jeepwork` 不直接读取企业工作空间内部数据（如某企业的具体线索内容）；如需统计，只读聚合后的平台级指标
3. 企业工作空间对象若需平台介入（如违规下架某企业产品），由 `/jeepwork/reports` → `/jeepwork/governance` 走处置流程，处置动作落地在企业工作空间，但处置记录在平台审计

## 5. 核心页面规范定义

> 通用字段说明：
> - **路由**：页面路径
> - **角色权限**：可见与可操作角色
> - **数据来源**：API 端点
> - **筛选条件**：列表筛选
> - **表格列**：列表展示字段
> - **详情字段**：详情页展示字段
> - **操作动作**：可执行操作
> - **危险等级**：低 / 中 / 高 / 极高
> - **二次确认**：是否需要二次确认
> - **审计要求**：是否记录不可抵赖审计
> - **空状态**：无数据时展示
> - **错误状态**：接口异常时展示
> - **无权限状态**：角色不足时展示
> - **系统降级状态**：依赖服务异常时展示
> - **验收标准**：上线前必须满足

## 6. 高风险操作统一流程

### 6.1 统一流程（9 步）

所有高风险操作必须严格按以下顺序执行，任何步骤缺失即视为违规：

```
1. 权限检查
   ├─ 校验当前管理员角色是否满足操作要求
   ├─ 校验 Session 有效性（未过期、未被强制下线）
   └─ 失败 → 返回 403，不进入下一步

2. 输入原因
   ├─ 操作人必须在表单中填写操作原因（不少于 10 字）
   ├─ 原因记录到审计日志
   └─ 失败 → 阻断操作

3. 风险预检
   ├─ 检查操作前置条件（如最后一名超管保护、未结订单、未处置举报）
   ├─ 检查操作副作用（如联动影响）
   └─ 失败 → 返回明确错误码与原因，不执行

4. 二次确认
   ├─ UI 弹出二次确认对话框，展示操作摘要、影响范围、不可逆提示
   ├─ 操作人必须勾选"我已知晓风险并确认执行"
   └─ 失败 → 阻断操作

5. 必要时二次身份验证
   ├─ 极高危险操作必须重新输入管理员密码
   ├─ 密码校验通过后生成一次性操作令牌（有效期 5 分钟）
   └─ 失败 → 阻断操作

6. 执行
   ├─ 在数据库事务中执行操作
   ├─ 失败 → 回滚事务，不产生部分副作用

7. 写入不可抵赖审计日志
   ├─ 操作人 ID、操作时间、IP、UA、操作类型、对象、原因、前后值、二次确认记录、二次身份验证记录
   ├─ 审计日志写入失败 → 触发熔断，回滚操作（如已执行则启动补偿流程）
   └─ 审计日志不可篡改、不可删除

8. 返回结果
   ├─ 成功 → 返回操作结果与影响摘要
   └─ 失败 → 返回错误码、原因、是否已回滚

9. 提供回滚或补偿信息
   ├─ 可逆操作 → 提供回滚入口
   ├─ 不可逆操作 → 提供补偿指引（如手动退款、人工通知）
   └─ 回滚/补偿动作本身也必须记录审计
```

## 8. 敏感数据脱敏规范

### 8.1 脱敏原则

1. **默认脱敏**：所有敏感字段在列表与详情中默认脱敏展示
2. **按需解敏**：仅在明确授权（super_admin + 二次身份验证）下解敏
3. **审计留痕**：每次解敏操作必须记录不可抵赖审计
4. **不落库明文**：解敏不写日志、不写缓存，仅当前请求返回

### 8.2 脱敏规则

| 字段类型 | 脱敏规则 | 示例 |
|----------|----------|------|
| 手机号 | 保留前 3 后 4，中间用 `****` | `138****1234` |
| 邮箱 | 用户名保留前 2，域名全显 | `zh****@example.com` |
| 身份证号 | 保留前 6 后 4，中间用 `********` | `110101********1234` |
| 银行卡号 | 保留后 4 | `************1234` |
| 商户私钥 | 仅展示前 4 与后 4，中间用 `****` | `MIIE****ABCD` |
| 支付宝公钥 | 仅展示前 4 与后 4 | `MIIB****EFGH` |
| API Key | 仅展示前 4 与后 4 | `sk-1****WXYZ` |
| Session Token | 仅展示前 8 | `sess_xxx****` |
| 密码 | 永不展示 | `********` |
| IP 地址 | 保留前 3 段，最后一段用 `*` | `1.2.3.*` |

### 8.3 解敏流程

1. 操作人提交解敏请求（携带对象 ID 与字段名）
2. 校验操作人为 super_admin
3. 二次身份验证（重新输入密码）
4. 记录不可抵赖审计（操作人、对象、字段、时间、IP、UA）
5. 返回明文（不写缓存、不写日志正文）

### 8.4 导出脱敏

- 批量导出默认全部脱敏
- 解敏导出必须 super_admin + 二次身份验证 + 原因
- 解敏导出文件必须含水印（操作人 ID + 时间）

## 10. 验收标准

### 10.1 通用验收标准（所有页面）

1. **权限隔离**：角色不足时返回 403，不暴露任何数据
2. **Session 隔离**：`link168_admin_session` 与 `link168_session` 物理隔离，互不干扰
3. **审计完整**：所有写操作记录不可抵赖审计，字段齐全
4. **脱敏生效**：敏感字段在列表与详情中默认脱敏
5. **错误可恢复**：接口失败时展示错误页 + 重试，不展示假数据
6. **空状态友好**：无数据时提供明确提示与"清除筛选"按钮
7. **降级提示**：依赖服务异常时显式标注已知限制
8. **二次确认**：高危险操作必须二次确认，极危险操作必须二次身份验证
9. **最后一名超管保护**：注销、修改角色必须通过 PG advisory lock 保护
10. **旧 `/admin` 已 404**：旧路由全部 `notFound()`

### 10.2 核心页面专项验收

| 页面 | 专项验收项 |
|------|------------|
| 总览 | 关键指标实时；已知限制可见；任一指标失败不影响整页 |
| 用户管理 | 邮箱/手机号脱敏；最后一名超管保护；批量导出记录审计；强制下线立即失效 Session |
| 主页管理 | 强制下架立即 410；删除前确认无未结订单；操作可回滚 |
| 会员管理 | 修改等级联动权益；补发权益走乐观锁 + 幂等键；显式标注"到期降级无定时任务" |
| 订单管理 | 手动对账记录对账人；退款二次确认 + 原因；联动会员降级；显式标注"退款未调用支付宝接口" |
| AI 用量 | 数据延迟 ≤ 5 分钟；冻结 AI 立即生效 |
| AI 成本 | 显式标注"Credit 计数 ≠ 真实成本"；真实成本列为【未来预留】；不展示假数据 |
| AI 安全 | 事件 5 分钟内出现；严重事件自动通知超管 |
| AI 设置 | 修改 Provider 二次身份验证；单价联动 ai-cost；限流联动 system-health |
