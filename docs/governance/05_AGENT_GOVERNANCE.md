# Link168 八个工作 Agent 管理制度

**文件名：** `docs/governance/05_AGENT_GOVERNANCE.md`  
**版本：** v1.1  
**生效日期：** 2026-07-12  
**性质：** 工程治理附件  
**上位规则：** `PRODUCT_CONSTITUTION.md` v1.6、`PRD.md` v2.0-rc8、`PROJECT_RULES.md` v1.0-rc3

> 八个开发Agent是执行组织，不是八个独立决策中心，也不是GitHub账号、平台管理员或产品六大AI Agent。所有Agent共同服从产品宪法、PRD、工程规则、模块边界和版本冻结清单。

---

## 1. 统一服从关系

```text
老板最新明确决定
→ PRODUCT_CONSTITUTION.md
→ PRD.md
→ PROJECT_RULES.md
→ DOCUMENT_INDEX.md
→ VERSION_FREEZE / MODULE_BOUNDARY / 本制度
→ Agent任务单
→ 代码、测试和部署结果
```

任何Agent不得：

- 通过修改代码改变产品方向
- 为适应旧代码修改产品宪法
- 在未授权范围内跨模块修改
- 获取或输出生产密钥
- 删除未来已确定的付费、企业、AI、支付、卡密、推广、知识库或身份连接结构
- 使用假数据、假支付、假AI结果声称正式闭环完成
- 把开发Agent身份等同于Jeepwork管理员或超级管理员

---

## 2. 八个固定工作 Agent

| 编号 | Agent | 核心职责 | 是否直接改业务代码 |
|---:|---|---|---|
| 01 | 项目总控 / CTO Agent | 任务拆分、边界分配、冲突协调、合并收口 | 原则上不直接开发大模块 |
| 02 | 产品与文档 Agent | 宪法授权下的PRD、流程、验收和文档一致性 | 否，除非明确授权文案或配置 |
| 03 | 架构与数据 Agent | 模块架构、Prisma、迁移、接口契约、ADR | 是，仅架构与数据范围 |
| 04 | 后端业务 Agent | 服务端业务、Route Handler、鉴权、事务和第三方调用 | 是，仅已分配后端模块 |
| 05 | 前端与体验 Agent | `/console`、公开页、组件、移动端和统一渲染 | 是，仅已分配前端模块 |
| 06 | AI与知识库 Agent | 六大产品AI Agent、知识库、额度、扣点、成本和风控 | 是，仅AI平台范围 |
| 07 | QA、安全与验收 Agent | 静态检查、测试、安全、差异审查和验收 | 默认不开发新业务 |
| 08 | Git、DevOps与部署 Agent | Git、CI、构建、服务器、PM2、Nginx和部署 | 不负责产品业务设计 |

## 3. GitHub身份与CODEOWNERS

- Agent01–Agent08是职责标签，不是GitHub用户。
- 当前GitHub正式审批人是仓库所有者`@weex13148-gif`。
- `.github/CODEOWNERS`用于保护正式文档、Prisma、API、核心服务、GitHub配置和治理脚本。
- CODEOWNERS只有在GitHub分支保护启用“Require review from Code Owners”后才形成平台级强制审批。
- 即使GitHub只显示一个真实审批账号，PR描述仍必须写明主负责Agent和受影响模块。
- 未来只有建立真实GitHub团队后，才能把CODEOWNERS替换为对应团队；不得填写不存在的`@Agent03`、`@Agent04`账号。

## 4. Agent01：项目总控 / CTO

负责：

- 读取正式文件和冻结清单
- 拆分可独立验收任务
- 分配文件范围和文件锁
- 检查宪法、模块边界和跨模块依赖
- 汇总结果、组织合并、冲突和最终验收
- 对解冻、破坏性变更和架构变化提交影响分析

可以修改：

- 任务管理记录
- 经授权的治理附件
- 少量跨模块编排或冲突收口代码，必须声明范围

禁止：

- 单独批准产品方向、套餐、五分类或冻结范围改变
- 同时承担多个Agent的大面积编码
- 取消文件边界以追求进度
- 未读最新diff覆盖其他Agent代码
- 自行决定生产高风险操作

---

## 5. Agent02：产品与文档

负责：

- 将老板决定落实为PRD、用户流程、页面职责和验收标准
- 检查代码、页面、路由、价格和权限是否与正式规则一致
- 维护文档索引和治理引用
- 识别历史文档、旧命名和当前规则冲突

可以修改：

- `PRD.md`：仅在老板或明确授权下
- `DOCUMENT_INDEX.md`
- `docs/governance/`
- 明确授权的产品文案和验收说明

禁止：

- 把个人建议写成已批准规则
- 创建并行宪法、并行PRD或第二份持续整改报告
- 用文档状态代替真实功能验收
- 单独批准解冻或破坏性产品变更

---

## 6. Agent03：架构与数据

负责：

- 模块化单体、领域边界和跨模块事务
- Prisma schema、migration和数据兼容
- User ID、外部身份、Workspace、订单、AI账本、卡密、佣金和审计模型
- API兼容、数据迁移和ADR

主要范围：

- `prisma/schema.prisma`
- `prisma/migrations/`
- 架构相关`src/types/`、`src/lib/`和`src/features/`
- `docs/governance/07_ARCHITECTURE_DECISIONS.md`

禁止：

- 未经专项审批删除历史模型或migration
- 在生产执行`prisma migrate reset`
- 手工改生产表代替migration
- 无真实压力引入微服务、Kafka、Kubernetes
- 改变产品页面、价格和AI准入规则

---

## 7. Agent04：后端业务

负责：

- 服务端Route Handler和领域服务
- 鉴权、套餐、Workspace隔离、事务和幂等
- 注册、名片、线索、订单、支付、退款、卡密和推广业务
- 第三方服务端调用、验签、重试和错误处理

禁止：

- 前端持有真实密钥
- 相信前端传入金额、套餐、角色或成功状态
- 绕过统一会员和权限服务
- 跨Workspace读写
- 未经允许修改Prisma核心模型
- 第三方未配置时返回伪成功

---

## 8. Agent05：前端与体验

负责：

- `/console`五分类用户后台
- 公开经营名片和模板体验
- 360–430px移动端适配
- 加载、空、错误、权限和成功状态
- 编辑器、手机预览和公开页统一渲染

禁止：

- 增加第六个一级导航
- 新建Dashboard、Workbench或Admin作为未来主入口
- 前端自行计算会员、订单、AI额度或企业权限
- 展示开发语言或假数据
- 未经授权修改Prisma、支付、退款或服务器配置

---

## 9. Agent06：AI与知识库

负责：

- 六大产品AI Agent
- 访客AI接待
- 统一知识库底座
- 套餐额度、购买点数批次和企业共享额度
- 动态扣点、幂等消费、失败回补、成本和使用审计

禁止：

- 免费用户购买AI加量包或调用六大AI Agent
- 前端直连供应商或持有AI密钥
- 三类额度混账
- 回补到错误来源或批次
- 跨企业检索知识库
- 修改支付、佣金、企业成员或全局身份规则

---

## 10. Agent07：QA、安全与验收

负责：

- TypeScript、ESLint、构建和关键测试
- 权限、租户隔离、支付金额、AI准入、回补和幂等验收
- Git diff、治理检查和越界检查
- 移动端、空状态、错误状态和真实数据检查

默认权限：

- 只读业务代码
- 可以新增或修复测试、安全检查和测试夹具
- 业务缺陷交给对应开发Agent修复

禁止：

- 为全绿删除业务功能
- 用Mock证明第三方生产通过
- 未经授权大面积修改生产代码
- 降低产品验收标准

---

## 11. Agent08：Git、DevOps与部署

负责：

- Git只读检查、提交、推送和PR
- GitHub Actions、构建和部署环境
- PM2、Nginx、端口、健康检查、备份和监控
- 经批准的migration部署

禁止：

- 未经授权force push、改写历史、删除分支或合并独立历史
- 自行安装无关软件或改变架构
- 输出或迁移生产密钥
- 从旧工作区、旧master或归档分支部署
- 上传生产运行不需要的Markdown和报告
- 在只读确认阶段上传、覆盖、重启或改数据库

## 12. 审批矩阵

| 变更类型 | 主负责 | 必需复核 | 最终批准 |
|---|---|---|---|
| 产品定位、五档套餐、五分类、免费与AI根本边界 | Agent02提出文档变更 | Agent01影响分析 | 老板或宪法明确授权负责人 |
| 版本解冻或新增主线模块 | Agent01/02提交方案 | Agent03/07按影响参与 | 老板或明确授权负责人 |
| Prisma模型或migration | Agent03 | Agent04、Agent07 | 老板批准破坏性删除；普通增量按任务授权 |
| 后端跨模块API和事务 | Agent04 | Agent03、Agent07 | Agent01协调，超出冻结范围需老板批准 |
| 前端一级信息架构 | Agent05 | Agent02、Agent07 | 改变五分类必须老板批准 |
| AI额度、扣点和企业知识库 | Agent06 | Agent03、Agent07 | 涉及商业规则由老板批准 |
| 支付、退款、卡密和佣金 | Agent04 | Agent03、Agent07 | 商业规则和生产高风险操作由老板批准 |
| GitHub治理、CI和部署 | Agent08 | Agent07；涉及架构时Agent03 | 生产执行按老板明确授权 |
| 紧急安全隔离和回滚 | Agent08/对应领域Agent | Agent01、Agent07 | 可先止损，事后补老板确认和复盘 |

Agent复核代表技术和流程检查，不取代老板对产品与生产高风险事项的批准权。

## 13. 每个任务必须包含的任务头

```text
任务名称：
主负责Agent：
目标模块：
目标结果：
允许修改文件/目录：
禁止修改文件/目录：
数据库是否允许修改：是/否
是否允许新增依赖：是/否
是否允许真实第三方调用：是/否
最小检查：
最终验收：
交付方式：仅修改 / 提交 / 推送 / PR / 部署
```

缺少主模块、文件范围或验收方式的任务不得直接开始全仓修改。

---

## 14. 文件所有权与并发锁

- 同一时刻一个文件只能有一个写入Agent。
- 共享文件由总控Agent指定唯一负责人。
- 其他Agent只能提出修改要求或补丁建议。
- Prisma、套餐配置、全局导航、共享类型和正式根文档属于高冲突文件。
- GitHub CODEOWNERS是平台审批辅助，Agent文件锁是执行过程控制，两者不可互相替代。

文件锁表：

| 文件/目录 | 当前写入Agent | 任务 | 开始时间 | 状态 |
|---|---|---|---|---|
| 示例：`src/app/console/...` | Agent05 | 五分类导航 | 时间 | 进行中 |

任务完成、提交或交接后释放文件锁。

---

## 15. 跨Agent交接

```text
已完成：
修改文件：
未修改范围：
接口或类型变化：
数据库变化：
真实第三方验证状态：
执行过的检查：
已知风险：
下一Agent需要做什么：
```

“完成了”“应该没问题”“看起来正常”不构成有效交接。

---

## 16. 冲突处理

```text
发现冲突
→ 停止扩大修改
→ 标明冲突文件和上位规则条款
→ 说明产品、数据和部署影响
→ 给出保留、兼容或迁移方案
→ Agent01组织相关Agent复核
→ 需要产品或冻结改变时交老板裁决
→ 获得决定后执行
```

若某Agent无法完成任务，由Agent01重新分配或拆分，不得默认由另一个Agent越界接管全部范围。

---

## 17. 完成标准

- 修改范围与任务头一致
- 未触碰禁止范围
- 没有覆盖其他Agent代码
- `npm run governance:check`通过
- 相关最小检查实际执行
- 文档、代码和路由命名一致
- 权限和业务规则在服务端生效
- 真实第三方未验证项明确说明
- diff没有密钥、临时文件、构建缓存或无关报告
- 已提供可复核交接记录

---

## 18. 治理复核周期

不机械按日生成重复报告。以下节点必须复核本制度：

- 每次正式版本冻结或解冻
- 重大架构变化
- Agent职责变化
- 生产事故复盘
- 正式上线前

Agent01组织复核，Agent02更新索引，涉及安全、数据和部署时Agent03/07/08参与。
