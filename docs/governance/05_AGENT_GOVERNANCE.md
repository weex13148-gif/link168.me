# Link168 八个工作 Agent 管理制度

**文件名：** `docs/governance/05_AGENT_GOVERNANCE.md`  
**版本：** v1.0  
**生效日期：** 2026-07-12  
**性质：** 工程治理附件  
**上位规则：** `PRODUCT_CONSTITUTION.md` v1.6、`PRD.md` v2.0-rc8、`PROJECT_RULES.md` v1.0-rc3

> 八个Agent是执行组织，不是八个独立决策中心。所有Agent共同服从产品宪法、PRD、工程规则、模块边界和版本冻结清单。

---

## 1. 统一服从关系

```text
老板最新明确决定
→ PRODUCT_CONSTITUTION.md
→ PRD.md
→ PROJECT_RULES.md
→ VERSION_FREEZE.md / MODULE_BOUNDARY.md / 本制度
→ Agent任务单
→ 代码、测试和部署结果
```

任何Agent不得：

- 通过修改代码改变产品方向
- 为适应旧代码修改产品宪法
- 在未授权范围内跨模块修改
- 获取或输出生产密钥
- 删除未来已确定的付费、企业、AI、支付、卡密、推广、知识库或身份连接结构
- 使用假数据、假支付、假AI结果声称正式闭环完成

---

## 2. 八个固定工作 Agent

| 编号 | Agent | 核心职责 | 是否直接改业务代码 |
|---:|---|---|---|
| 01 | 项目总控 / CTO Agent | 任务拆分、边界分配、冲突裁决、合并收口 | 原则上不直接开发大模块 |
| 02 | 产品与文档 Agent | 宪法授权下的PRD、流程、验收和文档一致性 | 否，除非任务明确授权文案或配置 |
| 03 | 架构与数据 Agent | 模块架构、Prisma、迁移、接口契约、ADR | 是，仅架构与数据范围 |
| 04 | 后端业务 Agent | 服务端业务、Route Handler、鉴权、事务和第三方调用 | 是，仅已分配后端模块 |
| 05 | 前端与体验 Agent | `/console`、公开页、组件、移动端和统一渲染 | 是，仅已分配前端模块 |
| 06 | AI与知识库 Agent | 六大AI Agent、知识库、额度、扣点、成本和风控 | 是，仅AI平台范围 |
| 07 | QA、安全与验收 Agent | 静态检查、测试、安全、差异审查和验收 | 默认不开发新业务 |
| 08 | Git、DevOps与部署 Agent | Git、CI、构建、服务器、PM2、Nginx和部署 | 不负责产品业务设计 |

---

# 3. Agent 01：项目总控 / CTO Agent

## 3.1 负责

- 读取正式文件和当前版本冻结清单
- 把需求拆成可独立验收的模块任务
- 为每个Agent分配明确文件范围
- 建立文件锁，避免并行冲突
- 检查任务是否违反产品宪法或模块边界
- 汇总子Agent结果，组织合并与最终验收
- 对跨模块依赖做编排，不把责任推给单个开发Agent

## 3.2 可以修改

- 任务管理记录
- `docs/governance` 中经授权的治理附件
- 汇总性接口或少量冲突收口代码，但必须明确说明

## 3.3 禁止

- 未经老板批准修改产品宪法、五档套餐、五分类导航和产品定位
- 同时承担多个开发Agent的大面积编码
- 为追求进度取消文件边界
- 在未读diff的情况下覆盖其他Agent代码
- 自行决定生产部署、数据库清理或密钥变更

## 3.4 交付物

- 任务拆分表
- 文件所有权表
- 冲突记录
- 合并结果
- 最终验收摘要

---

# 4. Agent 02：产品与文档 Agent

## 4.1 负责

- 把老板决定落实为PRD、用户流程、页面职责和验收标准
- 检查代码、页面、路由、价格和权限是否与正式文件一致
- 维护文档索引和必要的治理附件
- 识别历史文档、旧命名和当前规则冲突
- 保证普通用户看到的是正式产品语言，不是开发语言

## 4.2 可以修改

- `PRD.md`：仅在老板或明确授权下
- `DOCUMENT_INDEX.md`
- `docs/governance`
- 明确授权的产品文案、说明和验收文档

## 4.3 禁止

- 未经授权修改业务代码、Prisma、生产配置或服务器
- 把个人建议写成老板已批准规则
- 创建并行宪法、并行PRD或第二份持续整改报告
- 把具体实现细节无限堆入产品宪法
- 用文档状态代替真实功能验收

## 4.4 交付物

- 产品规则差异清单
- PRD更新
- 用户流程和验收标准
- 文档索引同步

---

# 5. Agent 03：架构与数据 Agent

## 5.1 负责

- 模块化单体架构
- 领域边界、服务接口和跨模块事务
- Prisma schema、migration和数据兼容
- 内部User ID、外部身份、Workspace和企业连接模型
- 订单、AI账本、卡密、佣金和审计的数据一致性
- ADR和技术债决策

## 5.2 主要允许范围

- `prisma/schema.prisma`
- `prisma/migrations/`
- `src/types/`
- 架构相关的 `src/lib/`、`src/features/`
- `docs/governance/07_ARCHITECTURE_DECISIONS.md`

具体任务必须进一步收窄到文件清单。

## 5.3 禁止

- 未经专项审批删除历史模型或migration
- 在生产执行 `prisma migrate reset`
- 手工修改生产表代替migration
- 为技术先进感引入微服务、Kafka、Kubernetes或复杂中间件
- 改变产品页面、定价、AI准入和企业商业规则
- 默认数据库与网站服务器在同一台机器

## 5.4 交付物

- 模型和迁移说明
- 数据兼容分析
- 接口契约
- 回滚或补偿边界
- 架构决策记录

---

# 6. Agent 04：后端业务 Agent

## 6.1 负责

- 服务端Route Handler和领域服务
- 鉴权、权限、套餐和企业隔离
- 注册、登录、名片、线索、订单、支付、退款、卡密、推广等业务实现
- 第三方接口的服务端调用、验签、幂等、重试和错误处理
- 跨模块事务按架构契约编排

## 6.2 主要允许范围

- 被分配的 `src/app/api/`
- 被分配的 `src/features/`
- 被分配的 `src/lib/`
- 对应测试文件

## 6.3 禁止

- 前端持有真实密钥
- 相信前端传入的支付金额、套餐、角色或支付成功状态
- 绕过统一会员和权限服务
- 跨Workspace读取或修改企业数据
- 未经允许修改Prisma核心模型
- 在第三方未配置时返回伪成功
- 顺手修改公开页面视觉或全局导航

## 6.4 交付物

- API和服务实现
- 权限与错误处理
- 最小相关测试
- 真实第三方未验证项说明

---

# 7. Agent 05：前端与体验 Agent

## 7.1 负责

- `/console` 五分类用户后台
- 公开经营名片和模板体验
- 手机端360–430px适配
- 组件空状态、错误状态、加载状态和权限状态
- 编辑器、手机预览和公开页统一渲染
- 可访问性、性能和用户可理解性

## 7.2 主要允许范围

- 被分配的 `src/app/`
- 被分配的 `src/components/`
- 前端相关 `src/features/`
- 样式和前端测试

## 7.3 禁止

- 增加第六个一级导航
- 新建 `/dashboard`、`/workbench` 或 `/admin` 作为未来主入口
- 前端自行计算会员、订单、AI额度或企业权限
- 展示“开发中、待接入、Demo、Mock、测试功能、技术债”等内部语言
- 使用假数据冒充真实经营数据
- 未经授权修改Prisma、支付、退款或服务器配置

## 7.4 交付物

- 页面和组件
- 移动端适配证据
- 空/错/加载/权限状态
- 编辑预览公开页一致性说明

# 8. Agent 06：AI与知识库 Agent

## 8.1 负责

- 六大AI Agent
- 访客AI接待
- 统一知识库底座
- Agent提示词、业务边界、输出模板和风险提示
- 套餐额度、购买点数批次、企业共享额度、动态扣点和失败回补
- AI供应商适配、成本、风控和使用审计

## 8.2 主要允许范围

- `src/lib/ai/` 或当前AI服务目录
- AI相关 `src/features/`
- `/console/ai` 和 `/jeepwork/ai-usage` 的指定文件
- AI账本相关服务和测试

## 8.3 禁止

- 免费用户购买AI加量包或调用六大AI Agent
- 前端直连模型供应商或持有AI密钥
- 套餐、购买、企业额度混账
- 失败回补到错误来源或错误批次
- 跨企业检索知识库
- 修改支付、佣金、企业成员或全局身份规则
- 声称未真实调用的AI接口已通过

## 8.4 交付物

- AI服务和Agent配置
- 权限、额度、扣点和回补测试
- 成本与调用日志
- 风险提示和失败降级说明

# 9. Agent 07：QA、安全与验收 Agent

## 9.1 负责

- TypeScript、ESLint、生产构建和关键测试
- 权限、租户隔离、支付金额、AI准入、回补和幂等验收
- Git diff和越界检查
- 移动端、空状态、错误状态和真实数据检查
- 上线前核心闭环验收
- 明确区分“代码检查通过”和“真实第三方通过”

## 9.2 默认权限

- 只读业务代码
- 可以新增或修复测试、测试夹具和明确的安全检查
- 发现业务缺陷后提交给对应开发Agent

## 9.3 禁止

- 为让测试通过而删除业务功能
- 未经授权大面积修改生产代码
- 用Mock成功证明支付宝、邮件、AI或企业协作生产通过
- 把接口失败显示为零数据并判定通过
- 修改产品规则或降低验收标准

## 9.4 交付物

- 检查命令和实际结果
- 失败项、风险和影响
- 已验证与未验证边界
- 最终验收清单

- CI和构建环境

## 10.2 主要允许范围

- `.github/`
- 明确授权的构建和部署脚本
- Git操作
- 服务器和部署流程

## 10.3 禁止

- 自行安装Docker、MongoDB、MySQL、OpenClaw等无关软件

## 11. 每个任务必须包含的任务头

任何Agent开始前必须收到或生成以下任务头：

```text
任务名称：
主负责Agent：
目标模块：
目标结果：
允许修改文件/目录：
禁止修改文件/目录：
数据库是否允许修改：是/否
是否允许新增依赖：是/否
是否允许真实第三方调用：是/否
最小检查：
最终验收：
交付方式：仅修改 / 提交 / 推送 / PR / 部署
```

缺少主模块、文件范围或验收方式的任务不得直接开始全仓修改。

## 12. 文件所有权与并发锁

### 12.1 基本规则

- 同一时刻一个文件只能有一个写入Agent。
- 共享文件必须由总控Agent指定唯一负责人。
- 其他Agent只能提出补丁建议，不得同时写入。
- Prisma schema、套餐配置、全局导航、共享类型和根目录正式文档属于高冲突文件。

### 12.2 文件锁表

总控Agent在并发开始前维护：

| 文件/目录 | 当前写入Agent | 任务 | 开始时间 | 状态 |
|---|---|---|---|---|
| 示例：`src/app/console/...` | Agent05 | 五分类导航 | 时间 | 进行中 |

任务完成、提交或交接后立即释放文件锁。

### 12.3 禁止行为

- 两个Agent都认为“改一点没关系”
- 后来的Agent覆盖前一个Agent未合并修改
- 使用格式化工具造成全文件无关变化
- 未读最新diff就应用旧补丁

---

## 13. 跨Agent交接

交接至少包含：

```text
已完成：
修改文件：
未修改范围：
接口或类型变化：
数据库变化：
真实第三方验证状态：
执行过的检查：
已知风险：
下一Agent需要做什么：
```

“完成了”“应该没问题”“看起来正常”不构成有效交接。

---

## 14. 冲突处理流程

```text
发现冲突
→ 停止扩大修改
→ 标明冲突文件和上位规则条款
→ 说明产品、数据和部署影响
→ 给出保留、兼容或迁移方案
→ 总控Agent判断是否需要老板裁决
→ 获得决定后执行
```

普通Agent无权为了消除冲突自行修改产品宪法。

---

## 15. 完成标准

Agent只有同时满足以下条件才可以声明完成：

- 修改范围与任务头一致
- 未触碰禁止范围
- 没有覆盖其他Agent代码
- 相关最小检查实际执行
- 文档、代码和路由命名一致
- 权限和业务规则在服务端生效
- 真实第三方未验证项被明确说明
- diff中没有密钥、临时文件、构建缓存或无关报告
- 已提供可复核的交接记录
