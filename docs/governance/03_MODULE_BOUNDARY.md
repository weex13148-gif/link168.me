# Link168 V2 模块边界

**文件名：** `docs/governance/03_MODULE_BOUNDARY.md`  
**版本：** v1.1  
**生效日期：** 2026-07-12  
**性质：** 工程治理附件  
**上位规则：** `PRODUCT_CONSTITUTION.md` v1.6、`PRD.md` v2.0-rc8、`PROJECT_RULES.md` v1.0-rc3

> 本文件用于防止Agent越界修改、业务规则重复实现和模块相互污染。十四个核心领域来自产品宪法；通知、配置、文件存储和监控属于平台支撑能力，不擅自升级为新的产品核心领域。

---

## 1. 总体原则

Link168采用模块化单体。所有模块在同一Next.js应用和PostgreSQL数据库中运行，但必须保持清晰责任边界。

1. 一个业务规则只能有一个服务端权威来源。
2. 页面层只负责展示、输入和交互，不负责核心权限、计费和状态裁决。
3. 模块之间通过明确服务、类型和数据接口协作，不直接依赖对方页面实现。
4. Agent每次只负责一个主模块和明确文件范围。
5. 跨模块变更由Agent01拆分责任，Agent03审查依赖，不得由单个Agent顺手全仓重构。
6. 未经批准不得删除支付、会员、AI、企业、卡密、推广、知识库和身份连接结构。
7. `crm`领域只代表轻量客户线索与跟进，不代表完整CRM产品线。

---

## 2. 允许的依赖方向

```text
页面与组件
    ↓
功能编排 / feature
    ↓
领域服务 / service
    ↓
数据访问、第三方适配、Prisma
```

禁止：

```text
页面直接计算会员权益
页面直接扣减AI额度
组件直接修改订单状态
第三方回调绕过领域服务写业务结果
企业连接器直接操作名片、客户和AI内部表
```

共享内容只允许进入：

- 稳定共享类型
- 通用鉴权和错误结构
- 日志、审计、幂等和事务基础设施
- 明确命名的领域服务接口

不得建立无边界的“万能service”“万能utils”承载所有业务。

---

## 3. 十四个核心领域总表

| 领域 | 核心责任 | 明确禁止 |
|---|---|---|
| `identity` | User、Session、邮箱注册登录、账号安全 | 开通会员、扣减AI额度、管理企业角色 |
| `social-identity` | 微信及企业协作外部身份绑定、冲突拦截 | 自动合并账号、直接赋予业务权限 |
| `card` | 经营名片、发布、公开页、联系方式 | 自行计算套餐、伪造访问或线索 |
| `card-components` | 页面组件、模板、主题、统一渲染 | 新增一级导航、复制多套渲染真相 |
| `catalog` | 产品与服务、上下架、展示、咨询入口 | 处理支付订单、跨租户读取 |
| `crm` | 轻量客户线索、状态、跟进、分配 | 扩张为完整CRM、群发或呼叫中心 |
| `analytics` | 访问、点击、短链、来源、转化 | 修改客户、订单或会员状态 |
| `billing` | 五档套餐、订单、支付宝、退款、会员 | 相信前端金额、保留退款后权益 |
| `redemption` | 卡密批次、兑换、冻结、作废 | 销售企业合同、独立实现会员权益 |
| `channel` | 推广员、归因、佣金、结算 | 多级分销、自买套佣、修改订单 |
| `ai-platform` | 六大AI、知识库、额度、扣点、回补 | 免费用户绕过、跨企业检索、混账 |
| `workspace` | 企业空间、成员、权限、企业资产 | 跨Workspace访问、自动获得Jeepwork权限 |
| `enterprise-integration` | 企业微信/飞书/钉钉连接器和成员生命周期 | 直接创建已激活用户、读取无关聊天正文 |
| `governance` | Jeepwork、举报、审计、安全、系统健康 | 普通管理员无边界权限、输出密钥 |

上述列表完整性由产品宪法第十章决定。新增第十五个核心领域必须先修改宪法并获得批准。

## 4. 核心领域详细边界

### 4.1 `identity`

负责：内部User ID、邮箱注册登录、Session、密码找回、账号冻结、申诉、注销和高风险身份校验。

拥有：User、Session、邮箱验证、密码重置、账号安全日志。

允许依赖：外部身份绑定结果、治理审计、邮件发送适配器。

禁止：以邮箱、手机号、OpenID或UnionID替代内部User ID；直接处理会员、AI额度和企业角色。

### 4.2 `social-identity`

负责：普通微信、企业微信、飞书、钉钉的外部身份授权、绑定、解绑、冲突和回调安全。

拥有：ExternalIdentity及授权、绑定、冲突记录。

允许依赖：`identity`识别User、`enterprise-integration`提供组织关系、`governance`写安全审计。

禁止：自动合并已有账号、覆盖占用身份、直接赋予会员或管理员权限、公开外部敏感标识。

### 4.3 `card`

负责：名片主体资料、保存发布、公开路径、联系方式、行动按钮和统一渲染编排。

允许依赖：组件、产品、分析、客户、会员权益和访客AI状态。

禁止：自行计算套餐、写订单或AI账本、公开企业内部数据、展示假结果。

### 4.4 `card-components`

负责：链接、图片、视频、二维码、公告、FAQ、模板、主题、背景、布局和空错误状态。

允许依赖：名片上下文、产品数据和模板权益。

禁止：创建新一级导航、决定会员身份、在正式页面硬编码假业务数据、复制独立渲染体系。

### 4.5 `catalog`

负责：产品与服务创建、编辑、上下架、公开展示、价格说明、详情和咨询来源快照。

允许依赖：所属名片、数量权益、访问分析和客户线索创建。

禁止：自行处理支付、客户跟进状态和跨Workspace查询。

### 4.6 `crm`

负责：真实线索、客户状态、兴趣产品、备注、跟进、来源、成员分配和重新分配。

允许依赖：名片、产品和AI来源上下文；Workspace权限；分析来源数据。

禁止：扩张为完整CRM、呼叫中心、私域群发、复杂营销自动化；成员离职时删除企业客户。

### 4.7 `analytics`

负责：公开页访问、链接点击、产品查看、短链、二维码、来源和转化聚合。

允许依赖：业务对象标识和套餐数据周期权益。

禁止：将接口失败伪装成零数据、向普通用户暴露原始高敏日志、修改业务状态。

### 4.8 `billing`

负责：五档套餐、服务端权益、订单、支付宝、退款、会员生命周期、价格快照和发票关联。

允许依赖：User、Workspace购买主体、推广归属、AI权益发放和审计。

禁止：相信前端金额或支付成功；允许免费用户通过加量包绕过准入；退款后保留相关权益。

### 4.9 `redemption`

负责：标准个人会员卡密的生成、批次、冻结、作废、哈希、有效期和兑换记录。

允许依赖：统一会员生效服务、渠道归属和管理审计。

禁止：销售企业版、企业Pro、长期合同、私有化或定制开发；明文输出完整卡密。

### 4.10 `channel`

负责：推广员申请审核、推广链接、订单归属、单层返佣、锁定、结算、提现和退款追缴。

允许依赖：用户身份、真实订单退款状态和治理审核。

禁止：多级分销、团队计酬、入门费、自买套佣、未支付生成可提现佣金。

### 4.11 `ai-platform`

负责：六大产品AI Agent、访客AI接待、知识库、套餐额度、购买批次、企业额度、动态扣点、回补、成本和供应商适配。

允许依赖：身份、套餐、Workspace、授权的名片产品客户上下文和治理风控。

禁止：免费用户绕过、前端持有密钥、三类额度混账、错误回补、跨企业知识库检索和保证高风险结论绝对正确。

### 4.12 `workspace`

负责：Workspace、成员、角色、席位、资源权限、企业品牌、主页、客户、知识库、AI和域名归属。

允许依赖：User、外部组织同步、企业套餐和审计。

禁止：访问其他Workspace；因离职删除企业资产；自动赋予Jeepwork权限；将企业版理解为个人会员数量叠加。

### 4.13 `enterprise-integration`

负责：企业协作统一连接层、平台适配器、外部企业/部门/成员映射、待激活、首次授权、离职、重试、幂等和同步游标。

允许依赖：外部身份、User、Workspace成员激活和治理审计。

禁止：把平台差异散落到业务模块；同步时批量创建已激活用户；第一阶段读取聊天正文、实现复杂审批或跨平台群发。

### 4.14 `governance`

负责：Jeepwork、用户治理、订单审核、举报、AI成本、系统健康、平台配置、管理员分权和安全审计。

允许依赖：各领域提供的只读查询或受控管理命令。

禁止：普通管理员获得超级管理员能力；绕过领域服务修改核心状态；输出密钥和敏感配置。

## 5. 平台支撑能力

这些能力横向服务多个领域，但不是新的产品核心领域。

### 5.1 通知与消息投递

负责：邮件、站内通知、未来企业协作通知的投递适配、重试、状态和模板渲染。

归属：基础实现由后端/治理维护，具体“为什么发送、发送给谁”由调用业务领域决定。

禁止：通知模块自行决定会员、支付、审核和企业权限结果；发送失败不得改写业务事实为成功。

### 5.2 配置与功能开关

负责：平台配置、第三方配置存在性、功能开关和安全读取。

归属：平台配置由`governance`管理；套餐、AI、支付等领域配置仍归各自领域。

禁止：把密钥返回前端；用功能开关永久代替正式权限；形成第二套套餐真相。

### 5.3 文件与对象存储

负责：上传、下载、类型大小校验、归属、访问控制和存储适配。

归属：基础设施可共享，文件业务归属仍由名片、产品、知识库等调用领域决定。

禁止：跨用户/Workspace访问；仅凭扩展名信任文件；公开私有资料。

### 5.4 可观测性与运行健康

负责：日志、指标、健康检查、告警、任务状态和故障关联标识。

归属：`governance`与Agent08维护，业务领域提供必要事件和指标。

禁止：日志记录密码、Token、密钥或不必要敏感正文；监控模块修改业务结果。

### 5.5 Console首页、设置和报表

- Console首页是跨领域只读聚合与行动编排层，不是独立业务领域。
- “我的/设置”是身份、会员、企业、推广等领域的入口组合，不拥有这些领域规则。
- 报表是`analytics`、`billing`、`ai-platform`和`governance`数据的授权视图，不建立第二套数据事实。

## 6. 跨模块事务

### 支付成功

```text
验证支付宝回调
→ 校验订单、金额、签名和幂等
→ 更新订单
→ 生效会员或AI点数批次
→ 写推广归属和锁定佣金
→ 写审计日志
```

### 退款

```text
确认退款结果
→ 更新订单和退款记录
→ 撤销或调整会员
→ 撤销AI额度或点数批次
→ 撤销/追缴佣金
→ 更新发票与审计
```

### 微信首次注册

```text
校验微信授权
→ 查询外部身份
→ 创建User ID和个人空间
→ 建立外部身份绑定
→ 创建Session
→ 写安全日志
```

### 企业成员首次激活

```text
校验外部授权与企业归属
→ 查找待激活成员
→ 复用或创建User ID
→ 激活WorkspaceMember
→ 绑定外部身份
→ 写生命周期和审计记录
```

上述流程必须由明确应用服务或事务编排完成，不得由多个页面各自拼接。

## 7. 跨模块变更审批

- 单模块内部变更：主负责Agent执行，对应QA复核。
- 两个及以上领域：Agent01拆分文件所有权，Agent03审查接口与事务。
- 涉及产品规则：Agent02核对PRD，改变冻结范围时交老板批准。
- 涉及Prisma或migration：Agent03主负责，Agent04/07复核。
- 涉及支付、身份、AI账本和企业隔离：必须进行专项服务端测试。
- PR必须在`.github/pull_request_template.md`中列明受影响模块。

## 8. Agent越界判定

出现以下任一情况即视为越界：

- 未声明修改第二个主模块
- 修改不在任务允许清单中的文件
- 为方便当前任务改写宪法、PRD或套餐规则
- 前端Agent修改Prisma核心模型
- AI Agent修改支付、佣金或企业权限
- 支付Agent修改公开名片渲染
- QA Agent以修复测试为名删除业务功能
- DevOps Agent改变产品架构、数据库目标或密钥
- 两个Agent同时修改同一文件

越界后停止扩大修改，记录冲突并交Agent01处理；涉及产品或冻结变化时交老板裁决。

---

## 9. 更新条件

只有以下情况更新本文件：

- 产品宪法新增或移除核心领域
- 模块责任正式迁移
- 权威数据来源改变
- 新第三方连接成为长期架构组成
- 模块拆分或合并获得批准
- 平台支撑能力归属发生变化

局部文件移动、样式调整和普通Bug修复不需要修改本文件。
