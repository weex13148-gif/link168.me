# Link168 V2 模块边界

**文件名：** `docs/governance/03_MODULE_BOUNDARY.md`  
**版本：** v1.0  
**生效日期：** 2026-07-12  
**性质：** 工程治理附件  
**上位规则：** `PRODUCT_CONSTITUTION.md` v1.6、`PRD.md` v2.0-rc8、`PROJECT_RULES.md` v1.0-rc3

> 本文件用于防止 Agent 越界修改、业务规则重复实现和模块相互污染。它不改变产品宪法、PRD或现有数据库事实。

---

## 1. 总体原则

Link168 当前采用模块化单体。所有模块在同一 Next.js 应用和 PostgreSQL 数据库中运行，但必须保持清晰责任边界。

统一原则：

1. 一个业务规则只能有一个服务端权威来源。
2. 页面层只负责展示、输入和交互，不负责核心权限、计费和状态裁决。
3. 模块之间通过明确服务、类型和数据接口协作，不直接读取对方内部实现。
4. Agent 每次只负责一个主模块和明确文件范围。
5. 跨模块变更必须由总控 Agent 先拆分责任，不得由单个 Agent 顺手全仓重构。
6. 未经批准不得删除未来已确定的支付、会员、AI、企业、卡密、推广、知识库和身份连接结构。

---

## 2. 允许的总体依赖方向

```text
页面与组件
    ↓
功能编排 / feature
    ↓
领域服务 / service
    ↓
数据访问、第三方适配、Prisma
```

禁止：

```text
页面直接计算会员权益
页面直接扣减AI额度
组件直接修改订单状态
第三方回调直接绕过领域服务写业务结果
企业连接器直接操作名片、客户和AI内部表
```

跨领域共享内容只允许放入：

- 稳定共享类型
- 通用鉴权与错误结构
- 日志、审计、幂等和事务基础设施
- 明确命名的领域服务接口

不得建立无边界的 `utils`、`helpers` 或“万能 service”承载所有业务。

# 3. 核心模块边界

## 3.1 `identity` 账号与会话

### 负责

- Link168 内部不可变 `User ID`
- 邮箱注册、登录、验证和密码找回
- Session、退出登录和会话安全
- 账号冻结、申诉、注销和数据导出入口
- 高风险操作身份校验

### 拥有或主导的数据

- User
- Session
- 邮箱验证记录
- 密码重置记录
- 账号安全日志

### 可以依赖

- `social-identity` 提供的外部身份绑定结果
- `governance` 提供的审计能力
- 邮件适配器

### 禁止

- 直接开通会员
- 直接计算AI额度
- 直接管理企业角色
- 以邮箱、手机号、OpenID 或 UnionID 替代内部 User ID 作为全局业务主键

---

## 3.2 `social-identity` 外部身份

### 负责

- 普通微信注册、登录和绑定
- 企业微信、飞书、钉钉外部身份绑定
- 外部身份冲突拦截
- 外部授权回调的验签、幂等和状态记录

### 拥有或主导的数据

- ExternalIdentity
- 外部授权状态
- 绑定、解绑和冲突记录

### 可以依赖

- `identity` 创建或识别 Link168 User ID
- `enterprise-integration` 提供企业组织关系
- `governance` 提供安全审计

### 禁止

- 自动合并两个已有 Link168 账号
- 覆盖已绑定到其他账号的外部身份
- 直接赋予会员、企业管理员或平台管理员权限
- 在前端或公开日志暴露外部平台敏感标识

---

## 3.3 `card` 经营名片

### 负责

- 名片主体资料
- 草稿、保存、发布和公开状态
- 公开路径 `/[username]`
- 联系方式、行动按钮和转化入口
- 手机预览与公开页统一渲染编排

### 拥有或主导的数据

- Profile
- 公开用户名
- 名片发布状态
- 名片基础字段

### 可以依赖

- `card-components` 获取组件配置和渲染能力
- `catalog` 获取产品与服务
- `analytics` 记录访问和点击
- `crm` 接收访客留资
- `billing` 获取品牌、数量和高级权益
- `ai-platform` 获取访客AI接待状态

### 禁止

- 自行计算套餐权益
- 自行写入订单或AI扣点
- 在公开页暴露企业内部数据
- 用假访问、假线索或假AI结果填充正式页面

---

## 3.4 `card-components` 名片组件与模板

### 负责

- 链接、图片、视频、二维码、公告、FAQ等页面组件
- 模板、主题、颜色、字体、背景和布局
- 编辑器、手机预览和公开页共用的渲染结构
- 组件空状态、错误状态和移动端适配

### 拥有或主导的数据

- ProfileModule 或对应组件配置
- Template / Theme 配置
- 组件排序和显隐

### 可以依赖

- `card` 提供名片上下文
- `catalog` 提供产品组件数据
- `billing` 提供模板和数量权益

### 禁止

- 创建新的一级导航
- 直接决定用户是否为会员
- 把业务数据硬编码为视觉示例并在正式页面展示
- 为单个页面复制一套独立渲染逻辑

---

## 3.5 `catalog` 产品与服务

### 负责

- 产品或服务创建、编辑、上下架和展示
- 标题、简介、价格说明、图片、详情和咨询入口
- 产品在公开名片中的展示
- 产品咨询来源快照

### 拥有或主导的数据

- Product / Service
- 上下架状态
- 产品展示配置

### 可以依赖

- `card` 获取所属名片
- `billing` 获取产品数量和高级展示权益
- `analytics` 记录产品访问
- `crm` 创建产品咨询线索

### 禁止

- 自行处理支付订单
- 自行创建客户跟进状态
- 跨用户或跨Workspace读取产品

---

## 3.6 `crm` 客户与线索

### 负责

- 公开名片、产品咨询和AI接待形成的真实线索
- 客户状态、来源、兴趣产品、备注和跟进记录
- 客户分配、重新分配和企业归属
- 用户可见的线索列表与转化状态

### 拥有或主导的数据

- Lead / Customer
- FollowUp / Note
- 分配和重新分配记录
- 客户状态

### 可以依赖

- `card`、`catalog` 和 `ai-platform` 提供来源上下文
- `workspace` 提供企业成员和资源权限
- `analytics` 提供来源与转化统计

### 禁止

- 扩张为完整CRM、呼叫中心或私域群发系统
- 把A企业客户分配给B企业成员
- 因成员离职删除企业客户和跟进记录
- 用前端状态代替服务端客户状态

---

## 3.7 `analytics` 访问与转化分析

### 负责

- 公开页访问、链接点击、产品查看和来源归因
- ShortLink、二维码和渠道参数
- 访问趋势、热门产品和转化漏斗
- 首页与客户页所需聚合数据

### 拥有或主导的数据

- ProfileVisit
- LinkClick
- ShortLink / ShortLinkClick
- AnalyticsEvent

### 可以依赖

- `card`、`catalog`、`crm` 提供业务对象标识
- `billing` 提供可查看的数据周期和分析权益

### 禁止

- 伪造零数据掩盖接口失败
- 把原始敏感IP和平台内部信息暴露给普通用户
- 直接修改客户、订单或会员状态

---

## 3.8 `billing` 会员、订单与支付

### 负责

- 五档套餐：免费版、Plus、Pro、企业版、企业Pro
- 套餐配置和服务端权益判断
- 订单、支付宝下单、签名、回调、退款和幂等
- 会员续费、升级、降级、到期和退款撤权
- 订单快照、价格一致性和发票关联

### 拥有或主导的数据

- Order
- MembershipSubscription
- Payment / Refund
- Entitlement / Plan 配置

### 可以依赖

- `identity` 获取用户
- `workspace` 获取企业购买主体
- `channel` 记录推广归属
- `ai-platform` 发放或撤销套餐AI权益
- `governance` 记录财务审计

### 禁止

- 相信前端传入的金额、套餐或支付成功状态
- 允许免费用户通过AI加量包绕过会员准入
- 退款后保留对应会员、AI、卡密或佣金权益
- 在多个页面或组件重复维护套餐真相

---

## 3.9 `redemption` 卡密

### 负责

- 标准化个人会员卡密的生成、批次、冻结、作废和兑换
- 卡密哈希、有效期、使用状态和兑换记录
- 兑换后调用统一会员生效规则

### 拥有或主导的数据

- RedemptionCode
- RedemptionBatch
- RedemptionLog

### 可以依赖

- `billing` 生效会员和订单快照
- `channel` 记录认证渠道归属
- `governance` 提供管理权限和审计

### 禁止

- 销售企业版、企业Pro、长期合同、私有化或定制开发
- 明文保存或输出完整卡密
- 创建独立于会员系统的权益生效逻辑

---

## 3.10 `channel` 推广与佣金

### 负责

- 推广员申请、审核和通知
- 推广链接、二维码、邀请码和订单归属
- 单层直接返佣
- 佣金锁定、结算、最低提现、退款追缴和审计

### 拥有或主导的数据

- Promoter / Channel
- ReferralAttribution
- CommissionLog
- Settlement / Withdrawal

### 可以依赖

- `identity` 获取推广员身份
- `billing` 获取真实有效订单与退款状态
- `governance` 获取审核和财务权限

### 禁止

- 多级分销、上下级返佣、团队计酬或拉人头奖励
- 自买套佣
- 未完成真实支付就生成可提现佣金
- 直接修改订单金额或支付状态

---

## 3.11 `ai-platform` AI平台

### 负责

- 六大AI Agent
- 访客AI接待
- 统一知识库底座
- 套餐额度、购买点数批次和企业共享额度
- 动态扣点、幂等消费、失败回补、成本和使用记录
- AI供应商适配和故障降级

### 拥有或主导的数据

- AI账户
- 套餐额度
- 购买点数批次
- 企业共享额度
- AiUsage / AiLedger
- 知识库和Agent配置

### 可以依赖

- `identity`、`billing`、`workspace` 校验身份、套餐和企业权限
- `catalog`、`card` 和 `crm` 提供授权业务上下文
- `governance` 提供风控和审计

### 禁止

- 免费用户调用六大AI Agent或购买AI加量包
- 前端直接持有模型密钥
- 套餐额度、购买额度和企业共享额度混为一个不可追踪余额
- 失败回补到错误额度来源或错误批次
- 跨企业检索知识库
- 冒充持证专业人士或保证高风险结果绝对正确

---

## 3.12 `workspace` 企业空间

### 负责

- Workspace、成员、角色、席位和资源权限
- 企业管理员与普通成员能力
- 企业品牌、主页、产品、客户、知识库、AI和域名的归属
- 企业成员离职后的资产保留和重新分配

### 拥有或主导的数据

- Workspace
- WorkspaceMember
- WorkspaceRole / Permission
- 企业资产归属和分配记录

### 可以依赖

- `identity` 获取统一User ID
- `enterprise-integration` 获取外部组织同步结果
- `billing` 获取企业套餐和席位
- `governance` 记录管理员操作

### 禁止

- 访问其他Workspace数据
- 因成员离职删除其所属企业的客户、名片和工作记录
- 自动赋予平台Jeepwork权限
- 把企业版理解为简单增加个人会员数量

---

## 3.13 `enterprise-integration` 企业协作连接

### 负责

- 企业微信、飞书、钉钉统一连接层
- 平台适配器
- 外部企业、部门、成员映射
- 待激活成员、首次授权激活、离职冻结和恢复
- 回调验签、重试、幂等、同步游标和错误记录
- 消息通知与Link168工作入口

### 拥有或主导的数据

- EnterpriseIntegration
- ExternalDepartment
- ExternalMember
- PendingWorkspaceMember
- 同步、回调和生命周期记录

### 可以依赖

- `social-identity` 识别外部身份
- `identity` 创建或识别User ID
- `workspace` 激活企业成员和分配权限
- `governance` 提供审计和系统健康

### 禁止

- 把三个平台差异散落到名片、客户和AI模块
- 通讯录同步时批量创建已激活用户
- 读取与Link168业务无关的聊天正文
- 第一阶段实现复杂审批、云文档双向同步或跨平台群发

---

## 3.14 `governance` 平台治理

### 负责

- `/jeepwork` 平台后台
- 用户、订单、举报、AI成本、系统健康和配置治理
- 管理员分权
- 安全、审计、内容审核和系统任务

### 拥有或主导的数据

- AdminAuditLog
- Report / Review
- 管理员角色与权限
- 系统健康和任务记录

### 可以依赖

- 各业务模块提供只读查询或受控管理命令

### 禁止

- 普通管理员获得无边界超级管理员权限
- 在用户导航展示Jeepwork入口
- 直接绕过业务模块修改会员、订单、AI和企业核心状态
- 输出生产密钥或敏感配置值

## 4. 跨模块事务规则

以下流程必须由明确的应用服务或事务编排完成：

### 支付成功

```text
验证支付宝回调
→ 校验订单、金额、签名和幂等
→ 更新订单
→ 生效会员或AI点数批次
→ 写推广归属和锁定佣金
→ 写审计日志
```

### 退款

```text
确认退款结果
→ 更新订单和退款记录
→ 撤销或调整会员
→ 撤销AI额度或点数批次
→ 撤销/追缴佣金
→ 更新发票与审计
```

### 微信首次注册

```text
校验微信授权
→ 查询外部身份
→ 创建User ID和个人空间
→ 建立外部身份绑定
→ 创建Session
→ 写安全日志
```

### 企业成员首次激活

```text
校验外部授权与企业归属
→ 查找待激活成员
→ 复用或创建User ID
→ 激活WorkspaceMember
→ 绑定外部身份
→ 写生命周期和审计记录
```

上述步骤不得由多个页面各自拼接，也不得出现一半成功、一半失败却没有补偿记录的状态。

## 5. Agent越界判定

出现以下任一情况即视为越界：

- 未声明就修改第二个主模块
- 修改不在任务允许清单中的文件
- 为方便当前任务改写产品宪法、PRD或套餐规则
- 前端Agent修改Prisma核心模型
- AI Agent修改支付、佣金或企业权限
- 支付Agent修改公开名片渲染
- QA Agent以“修复测试”为名删除业务功能
- DevOps Agent改变产品架构、数据库目标或密钥
- 两个Agent同时修改同一文件

越界后必须停止继续扩大修改，记录冲突并交由总控Agent处理。

---

## 6. 变更本文件的条件

只有以下情况需要更新模块边界：

- 产品宪法新增或移除核心领域
- 模块责任正式迁移
- 权威数据来源改变
- 新第三方连接成为长期架构组成
- 模块拆分或合并获得老板批准

局部文件移动、样式调整和普通Bug修复不需要修改本文件。
