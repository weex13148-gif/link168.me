## 2. 优先级定义

- **P0：** 阻塞当前真实主闭环、上线、安全或关键数据一致性的事项，必须优先完成。
- **P1：** P0稳定后进入的重要增强，可保留结构，但不能抢占P0资源。
- **P2：** 后续规模化、体验或运营增强，不作为当前版本阻塞项。

P0/P1/P2用于产品和开发优先级，不用于生产事故严重度；生产事故使用SEV等级。

## 3. 已冻结的产品身份

未经老板明确批准不得改变：

- 产品名称：`Link168`
- 官方域名：`link168.me`
- 产品定位：面向自媒体、小商家、一人公司和轻量经营团队的AI SaaS经营名片工具与商业基础设施平台
- 核心闭环：注册 → 创建名片 → 发布分享 → 访客访问与留资 → 客户跟进 → 数据分析 → 会员付费 → AI经营
- 主产品不是完整CRM、ERP、通用AI聊天站、私域群发系统或多级分销系统
- Showcase只允许受控入口，不得在普通首页展示入口

### 3.1 轻量客户域与完整CRM的区别

产品宪法中的`crm`核心领域只表示：

- 客户线索
- 客户状态
- 跟进记录
- 来源归因
- 企业内分配和重新分配

本清单禁止的是扩张为完整CRM产品线，例如复杂销售自动化、呼叫中心、全渠道群发、复杂审批和大型客户运营套件。两者不冲突。

## 4. 已冻结的信息架构

用户后台一级分类永久固定为：

1. 首页
2. 名片
3. 客户
4. AI
5. 我的

冻结规则：

- 手机端使用五项固定底部导航。
- 桌面端可以改变布局，但名称、顺序和职责不变。
- 不增加第六个、第七个一级导航。
- 产品、模板、二维码、短链、数据、会员、订单、知识库、AI加量包、推广、企业空间、域名和协作平台连接均作为组件或二级页面。
- 用户侧统一入口为`/console`。
- 平台后台统一为`/jeepwork`。
- 普通用户和企业管理员导航不得出现Jeepwork平台入口。

## 5. 已冻结的套餐与AI边界

正式五档结构：

1. 免费版
2. Plus
3. Pro
4. 企业版
5. 企业Pro

冻结规则：

- 免费版必须完成基础经营名片闭环。
- 免费用户不赠送真实AI额度。
- 免费用户不获得六大AI Agent套餐权益。
- 免费用户不允许购买AI加量包。
- 加量包页面和订单API必须由服务端拒绝免费用户。
- Plus、Pro、企业版和企业Pro可以按对应权益使用AI和购买加量包。
- 套餐额度、购买点数批次和企业共享额度必须分账。
- 每笔AI加量包独立90天有效，优先消耗最早到期批次。
- AI失败、超时或平台错误必须回补到原额度来源和原批次。
- 六大AI Agent固定为：财税助手、法务助手、市场调研助手、设计助手、社媒运营助手、销售顾问。

具体价格、点数、席位和佣金可依据老板批准更新PRD和配置，但不得创建第六档正式套餐。

## 6. 已冻结的统一身份规则

- Link168内部不可变`User ID`是唯一主账号标识。
- 邮箱、普通微信、企业微信、飞书和钉钉是可绑定身份，不是业务主键。
- 普通用户可通过微信直接注册，不要求先填写邮箱。
- 微信首次注册创建内部User ID和个人空间。
- 已登录用户在“我的 → 账号安全/身份绑定”绑定微信。
- 已被其他账号绑定的外部身份不得覆盖或自动合并。
- 微信直接注册且未填写邮箱的用户，不适用30天未验证邮箱冻结。
- 邮箱注册用户仍适用30天验证规则。
- 一个自然人原则上只对应一个Link168主账号，可同时拥有个人空间和多个企业身份。

## 7. 已冻结的企业成员生命周期

通讯录同步正式流程：

```text
同步企业通讯录
→ 创建待激活企业成员
→ 成员首次通过对应平台授权登录
→ 创建或识别Link168主账号
→ 激活企业成员身份
→ 绑定Workspace和外部组织身份
```

离职正式流程：

```text
检测成员离职或停用
→ 冻结企业访问权
→ 保留个人Link168账号
→ 企业客户、企业名片和工作记录继续归企业
→ 未完成客户和任务由管理员重新分配
```

冻结规则：

- 通讯录同步不得直接批量创建已激活用户。
- 待激活成员没有企业数据访问权，不自动产生个人会员、AI额度或个人名片。
- 已有Link168账号的成员激活时复用原User ID。
- 离职不删除个人空间和个人合法数据。
- 企业客户、企业名片、知识库、任务和工作记录不得因成员离职转为个人数据或被删除。
- 企业数据必须按Workspace隔离。

## 11. 当前禁止扩张的范围

未经老板新增批准，不得开发为正式主线：

- 完整CRM
- 完整ERP
- OA和复杂审批系统
- 私域群发和跨平台群发
- 通用AI聊天网站
- 读取企业微信、飞书或钉钉聊天正文
- 云文档双向同步
- 客户数据跨平台双向覆盖
- 复杂营销自动化
- 第六个用户后台一级导航
- 与经营名片、获客、客户、会员、AI或企业协作无关的大型工具集合
- 为技术先进感引入微服务、Kubernetes、Kafka或复杂中间件

已有兼容代码、字段、路由或历史模型不得因为处于禁止扩张范围而被直接删除。

- 修改产品宪法以适应现有代码

- 把生产密钥写入仓库、报告、日志或前端
- 用简单关键词扫描阻止CRM、Dashboard、Workbench等合法兼容代码或历史说明

## 15. 解冻与例外流程

### 15.1 提案权与批准权

- Agent01、Agent02或对应领域Agent可以提交解冻建议。
- Agent01负责影响分析和协调，不拥有单独改变产品方向的权力。
- Agent02负责把批准决定写入PRD，不拥有单独改变宪法的权力。
- 只有老板或产品宪法明确授权的负责人可以批准改变冻结范围。

### 15.2 解冻条件

- 老板明确改变产品方向、用户、五档套餐、五分类导航或免费与AI边界
- P0主闭环完成并进入下一正式版本
- 已批准首个企业协作平台和实施方案
- 真实业务压力证明需要架构拆分
- 现有冻结规则与法律、合规或生产安全发生冲突

### 15.3 必需材料

1. 变更原因和证据。
2. 受影响的宪法、PRD、工程规则、代码和数据。
3. 迁移、兼容和回滚方案。
4. 老板或明确授权负责人的批准记录。
5. 正式文档、索引、本清单和持续整改报告同步更新。

### 15.4 紧急例外

生产安全、数据泄露、支付错账或大面积不可用时，可以先执行最小隔离、降级或回滚，但不能借紧急修复扩大产品范围。事故结束后必须补充批准、复盘和文档更新。
