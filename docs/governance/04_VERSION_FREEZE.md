## 2. 优先级定义

- **P0：** 阻塞当前真实主闭环、上线、安全或关键数据一致性的事项，必须优先完成。
- **P1：** P0稳定后进入的重要增强，可保留结构，但不能抢占P0资源。
- **P2：** 后续规模化、体验或运营增强，不作为当前版本阻塞项。

P0/P1/P2用于产品和开发优先级，不用于生产事故严重度；生产事故使用SEV等级。

## 3. 已冻结的产品身份

未经老板明确批准不得改变：

- 产品名称：`Link168`
- 官方域名：`link168.me`
- 产品定位：面向自媒体、小商家、一人公司和轻量经营团队的AI SaaS经营名片工具与商业基础设施平台
- V2核心闭环：邮箱注册 → 创建名片 → 发布分享 → 访客访问与留资 → 客户跟进 → 数据分析 → 会员付费 → AI经营
- 主产品不是完整CRM、ERP、通用AI聊天站、私域群发系统或多级分销系统
- Showcase只允许受控入口，不得在普通首页展示入口

### 3.1 轻量客户域与完整CRM的区别

产品宪法中的`crm`核心领域只表示：

- 客户线索
- 客户状态
- 跟进记录
- 来源归因
- 企业内分配和重新分配

本清单禁止的是扩张为完整CRM产品线，例如复杂销售自动化、呼叫中心、全渠道群发、复杂审批和大型客户运营套件。两者不冲突。

## 4. 已冻结的信息架构

用户后台一级分类永久固定为：

1. 首页
2. 名片
3. 客户
4. AI
5. 我的

冻结规则：

- 手机端使用五项固定底部导航。
- 桌面端可以改变布局，但名称、顺序和职责不变。
- 不增加第六个、第七个一级导航。
- 产品、模板、二维码、短链、数据、会员、订单、知识库、AI加量包、推广、企业空间、域名和设置均作为组件或二级页面。
- 用户侧统一入口为`/console`。
- 平台后台统一为`/jeepwork`。
- 普通用户和企业管理员导航不得出现Jeepwork平台入口。
- V2用户页面不得展示普通微信登录、微信绑定或企业协作平台连接入口。

## 5. 已冻结的套餐与AI边界

正式五档结构：

1. 免费版
2. Plus
3. Pro
4. 企业版
5. 企业Pro

冻结规则：

- 免费版必须完成基础经营名片闭环。
- 免费用户不赠送真实AI额度。
- 免费用户不获得六大AI Agent套餐权益。
- 免费用户不允许购买AI加量包。
- 加量包页面和订单API必须由服务端拒绝免费用户。
- Plus、Pro、企业版和企业Pro可以按对应权益使用AI和购买加量包。
- 套餐额度、购买点数批次和企业共享额度必须分账。
- 每笔AI加量包独立90天有效，优先消耗最早到期批次。
- AI失败、超时或平台错误必须回补到原额度来源和原批次。
- 六大AI Agent固定为：财税助手、法务助手、市场调研助手、设计助手、社媒运营助手、销售顾问。

具体价格、点数、席位和佣金可依据老板批准更新PRD和配置，但不得创建第六档正式套餐。

## 6. 已冻结的V2身份规则

- Link168内部不可变`User ID`是唯一主账号标识。
- V2只开放邮箱注册和登录。
- 邮箱是V2登录身份，但不能作为订单、会员、AI额度、名片或企业角色的业务主键。
- 邮箱验证不阻断首次注册；注册30天未验证按规则冻结。
- 首次注册不强制手机号，高风险操作可要求已验证邮箱或中国大陆手机号。
- V2不开发普通微信注册、登录或绑定。
- V2不开发两个已有账号合并。
- V2不开发最后一个登录身份解绑。
- 已有普通微信或其他外部身份相关代码、字段、路由和接口结构默认保留、隐藏或关闭，未经批准不得删除或启用。

## 7. 已冻结的V2企业成员规则

V2不接入企业微信、飞书和钉钉。企业成员采用Link168站内邮箱邀请：

```text
企业管理员发送邮箱邀请
→ 受邀者注册或登录Link168
→ 接受邀请
→ 创建或激活WorkspaceMember
→ 获得被授权的企业访问权
```

冻结规则：

- 邀请必须绑定Workspace、邮箱、角色、邀请人和有效期。
- 邀请未接受前没有企业数据访问权。
- 已有Link168账号复用原User ID。
- 接受邀请不得重复创建成员或重复占用席位。
- 企业管理员可手工冻结、移除和恢复成员。
- 冻结或移除后立即失去企业访问权，但保留个人账号和个人合法数据。
- 企业客户、企业名片、知识库、任务和工作记录继续归企业。
- 企业数据必须按Workspace隔离。
- 企业管理员不得查看成员密码、私人会话、个人空间数据或AI对话正文。

## 11. 当前禁止扩张的范围

未经老板新增批准，不得开发为V2正式主线：

- 普通微信登录、绑定和授权回调
- 企业微信、飞书或钉钉真实连接
- 外部通讯录和部门同步
- 账号合并和最后身份解绑
- 多平台成员去重
- 企业管理员查看成员AI对话正文
- 完整CRM
- 完整ERP
- OA和复杂审批系统
- 私域群发和跨平台群发
- 通用AI聊天网站
- 读取企业微信、飞书或钉钉聊天正文
- 云文档双向同步
- 客户数据跨平台双向覆盖
- 复杂营销自动化
- 第六个用户后台一级导航
- 与经营名片、获客、客户、会员、AI或企业空间无关的大型工具集合
- 为技术先进感引入微服务、Kubernetes、Kafka或复杂中间件

已有兼容代码、字段、路由或历史模型不得因为处于禁止扩张范围而被直接删除。

- 修改产品宪法以适应现有代码
- 创建并行宪法、并行PRD或第二份持续整改报告
- 启用或开发V2已延后的微信、企业协作、账号合并和多平台能力
- 删除支付、会员、AI、企业、卡密、推广、知识库、身份连接或未来扩展结构
- 两个Agent同时修改同一文件
- 为当前任务顺手进行全仓重构
- 使用假数据、假支付、假AI结果声称闭环完成
- 无真实环境记录却声称支付宝、邮件、AI或企业协作已通过
- force push、改写历史、合并独立历史或删除正式分支
- 把生产密钥写入仓库、报告、日志或前端
- 用简单关键词扫描阻止CRM、Dashboard、Workbench等合法兼容代码或历史说明

## 15. 解冻与例外流程

### 15.1 提案权与批准权

- Agent01、Agent02或对应领域Agent可以提交解冻建议。
- Agent01负责影响分析和协调，不拥有单独改变产品方向的权力。
- Agent02负责把批准决定写入PRD，不拥有单独改变宪法的权力。
- 只有老板或产品宪法明确授权的负责人可以批准改变冻结范围。

### 15.2 解冻条件

- 老板明确改变产品方向、用户、五档套餐、五分类导航或免费与AI边界
- P0主闭环完成并进入下一正式版本
- 老板重新批准普通微信或企业协作平台进入某一版本
- 真实业务压力证明需要架构拆分
- 现有冻结规则与法律、合规或生产安全发生冲突

### 15.3 必需材料

1. 变更原因和证据。
2. 受影响的宪法、PRD、工程规则、代码和数据。
3. 迁移、兼容和回滚方案。
4. 老板或明确授权负责人的批准记录。
5. 正式文档、索引、本清单和持续整改报告同步更新。

### 15.4 紧急例外

生产安全、数据泄露、支付错账或大面积不可用时，可以先执行最小隔离、降级或回滚，但不能借紧急修复扩大产品范围。事故结束后必须补充批准、复盘和文档更新。
