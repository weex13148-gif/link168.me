# ADR-001：采用模块化单体

**状态：** Accepted  
**日期：** 2026-07-12  
**依据：** 产品宪法第十章

## 背景

Link168当前是一人公司主导、AI Agent协作开发的真实SaaS。业务正在统一账号、名片、客户、会员、AI和企业空间，尚未出现必须拆分微服务的团队规模和流量压力。

## 决策

继续采用：

```text
Next.js模块化单体
+ PostgreSQL
+ Prisma
+ 清晰领域边界
```

不为技术先进感提前引入微服务、Kubernetes、Kafka或复杂分布式中间件。

## 结果

- 所有领域在同一仓库和部署单元中。
- 通过模块边界、服务接口、事务和Agent文件锁维持隔离。
- 高负载能力只有在真实性能、团队或合规证据出现后才拆分。
- 未来拆分时优先选择边界清晰、负载独立的模块，而不是按页面拆分。

# ADR-002：内部User ID是唯一主账号标识

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

Link168长期支持邮箱、普通微信、企业微信、飞书和钉钉。如果直接以邮箱、OpenID、UnionID或手机号作为主键，会造成身份冲突、企业成员重复、订单和会员归属混乱。

## 决策

- 使用内部不可变 `User ID` 作为唯一主账号标识。
- 邮箱、微信和企业协作身份作为 `ExternalIdentity` 或等价外部身份绑定。
- 订单、会员、AI额度、名片和企业角色关联内部User ID或Workspace。
- 同一外部身份已绑定其他账号时停止操作，不自动覆盖或合并。

## 结果

- 微信可直接注册且不要求先填写邮箱。
- 一个用户可绑定多个身份并加入多个企业空间。
- 账号合并必须另行设计安全流程。
- 现有强制邮箱约束需要通过兼容migration逐步调整。

# ADR-003：用户后台固定五个一级分类

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

旧 `/dashboard`、`/workbench` 和不断新增入口造成用户后台复杂、移动端拥挤和产品心智分裂。

## 决策

用户后台固定为：

```text
首页 / 名片 / 客户 / AI / 我的
```

- 手机端使用固定底部导航。
- 桌面端可使用侧栏或顶部栏，但名称、顺序和职责不变。
- 其他能力全部组件化或进入二级页面。
- 用户侧新能力统一进入 `/console`。

## 结果

- 不新增第六个一级导航。
- `/dashboard`、`/workbench` 只作为兼容或迁移来源。
- 企业空间从“我的”进入。
- 产品、模板、数据、会员、推广和域名不再独占一级导航。

# ADR-004：平台后台唯一使用Jeepwork

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

旧 `/admin` 与Jeepwork并存会造成双后台、权限重复和普通用户导航误暴露。

## 决策

- 平台后台统一为 `/jeepwork`。
- 平台管理员按客服、审核、财务、渠道、企业服务、系统和超级管理员分权。
- 企业管理员只管理本企业，不自动获得Jeepwork权限。
- 普通用户导航不得展示Jeepwork入口。

## 结果

- 新平台管理能力只进入Jeepwork。
- 旧 `/admin` 不作为V2目标入口。
- 高风险管理操作必须记录审计日志。

# ADR-005：账号、套餐、权限和额度使用唯一服务端来源

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

如果页面、组件、API各自维护会员、角色、AI额度或套餐规则，会造成前后端不一致、免费用户绕过限制和订单状态失真。

## 决策

下列规则必须有唯一服务端权威来源：

- 账号和外部身份
- 套餐和会员状态
- 页面与API权限
- AI套餐额度
- AI购买点数批次
- 企业共享额度
- 订单与退款
- 卡密与推广归属
- 佣金
- Workspace租户和资源权限

页面只展示服务端结果，不自行裁决核心规则。

## 结果

- 套餐键和权益配置集中维护。
- API必须重复校验，不信任前端隐藏或禁用状态。
- 普通用户无法通过URL和脚本绕过权限。
- 数据和权限问题优先修复服务端来源，而不是增加页面判断。

# ADR-006：AI使用三类额度分账和独立批次

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

套餐额度、用户现金购买点数和企业共享额度的来源、有效期、退款和所有权不同。如果混成一个余额，无法正确扣减、回补和审计。

## 决策

AI额度分为：

1. 套餐额度
2. 购买点数批次
3. 企业共享额度

规则：

- 免费用户不能购买AI加量包。
- 每笔购买点数独立90天有效。
- 多批次优先消耗最早到期批次。
- 调用记录保存模型、Agent、来源、批次、扣点、成本和状态。
- 失败、超时或平台错误回补到原来源和原批次。

## 结果

- 不能仅维护一个 `balance` 字段代表全部AI权益。
- 支付、退款、到期和企业分配必须能定位具体额度来源。
- 高成本模型和工具调用可以采用动态扣点。

# ADR-007：企业协作平台采用统一连接层与适配器

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

企业微信、飞书和钉钉的授权、成员标识、回调和组织结构不同。如果差异直接散落到名片、客户、AI和企业页面，后续难以维护和替换。

## 决策

建立统一 `enterprise-integration` 连接层：

```text
统一企业连接接口
├─ WeCom Adapter
├─ Feishu Adapter
└─ DingTalk Adapter
```

统一处理：

- 外部企业与Workspace绑定
- 部门和成员映射
- 待激活、在职、离职和停用
- 授权、验签、幂等、重试和同步游标
- 消息通知和工作入口

## 结果

- 业务模块只依赖统一连接接口。
- 首个实施平台仍需老板决定。
- 第一阶段不读取聊天正文，不做复杂审批、云文档双向同步和跨平台群发。

# ADR-008：通讯录同步只创建待激活成员

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

直接把企业通讯录批量转换为已注册Link168用户，会制造无授权账号、虚假活跃用户、席位重复和个人数据问题。

## 决策

通讯录同步只创建待激活企业成员：

```text
同步通讯录
→ PendingWorkspaceMember
→ 成员首次授权
→ 创建或识别User ID
→ 激活WorkspaceMember
```

## 结果

- 待激活成员没有企业数据访问权。
- 待激活成员不自动获得个人会员、AI额度或个人名片。
- 已有Link168账号的成员激活时复用原User ID。
- 同一成员不得重复激活或重复占用席位。

# ADR-009：成员离职时保留个人账号与企业资产

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

企业成员同时可能拥有个人空间。离职时删除整个User会损害个人权益；把企业客户和工作记录转给个人又会损害企业权益。

## 决策

- 冻结离职成员的企业访问权。
- 保留其个人Link168账号、个人空间和个人合法数据。
- 企业客户、成员企业名片、知识库、任务和工作记录继续归企业。
- 未完成客户和任务由企业管理员重新分配。
- 全过程记录审计。

## 结果

用户身份、个人资产和企业资产必须在数据模型中明确区分，不能依赖页面归属推断。

# ADR-010：支付和第三方回调必须真实、幂等、可补偿

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

支付、邮件、AI、微信和企业协作均依赖第三方服务。网络重试、重复回调和部分失败会造成重复开通、重复扣点或半完成账号。

## 决策

所有重要第三方流程必须具备：

- 服务端验签
- 请求和回调幂等
- 明确状态机
- 重试或补偿
- 错误记录
- 真实成功证据

正式产品不得用前端模拟或假结果冒充第三方成功。

## 结果

- 支付回调必须校验订单、金额、签名和重复通知。
- 微信注册的User、身份绑定和个人空间应在事务或可靠补偿中完成。
- AI扣点失败必须回补。
- 企业组织同步必须可重试并记录游标和错误。
- 未配置真实服务时明确返回不可用，不伪造成功。

# ADR-011：保留优先，未完成功能使用开关、隐藏或降级

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

历史开发中曾出现为当前收口直接删除未来付费、企业和AI结构，导致重复开发和数据风险。

## 决策

对已经由宪法确认的未来能力采用：

- 保留代码和数据结构
- 隐藏入口
- 功能开关
- 服务端权限限制
- 降级或只读

删除页面、路由、字段、模型、迁移或未来能力前必须列出清单、依赖、数据影响和迁移方案，并获得老板批准。

## 结果

- “当前不开放”不等于“删除结构”。
- Showcase相关历史模型不得被Agent顺手删除。
- 旧路径可以兼容跳转，稳定后再专项清理。

# ADR-012：编辑器、手机预览和公开页统一渲染

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

独立实现编辑器预览和公开页会造成样式、组件顺序、空状态和移动端结果不一致。

## 决策

尽量复用同一组件模型、主题解析和渲染核心：

```text
组件配置
→ 统一解析
→ 编辑器画布 / 手机预览 / 公开页
```

编辑状态控制和公开访问逻辑可以不同，但最终视觉组件和数据解释应保持一致。

## 结果

- 组件修改优先修复共享渲染层。
- 不为单个页面复制完整模板实现。
- 360–430px移动端作为首要验收范围。

# ADR-013：正式文档只保留四份，治理附件从属

**状态：** Accepted  
**日期：** 2026-07-12

## 背景

多个PRD、宪法和整改报告并存会让Agent引用不同版本。

## 决策

正式权威文件只保留：

```text
PRODUCT_CONSTITUTION.md
PRD.md
PROJECT_RULES.md
DOCUMENT_INDEX.md
```

`docs/governance/` 中的代码地图、模块边界、冻结清单、Agent制度、命名标准、ADR和开发规则全部是从属执行附件。

唯一持续整改状态保留在：

```text
docs/audits/REMEDIATION_DEVELOPMENT_REPORT.md
```

## 结果

- 不创建第二份宪法、PRD或持续整改报告。
- 治理附件冲突时服从正式根目录文件。
- `DOCUMENT_INDEX.md` 记录治理附件版本和状态。
