## 1. 文档目标与定位

### 1.1 最高前提（不可妥协）

Link168 是已真实上线的生产级 SaaS 产品，服务于真实用户、真实公开名片、真实会员、真实支付、真实 AI 调用、真实客户线索、真实数据治理和真实生产运维。

`/showcase` 仅是 Link168 面向以下外部场景的【受控外部展示与可信证据入口】：

- TRAE 创业比赛
- 评委评审
- 投资人尽调
- 政府园区考察
- 合作方接入对接
- 阶段性验收

### 1.2 产品本体 ≠ /showcase 展示入口

| 维度 | 产品本体 | /showcase 展示入口 |
| --- | --- | --- |
| 定位 | 真实生产服务 | 受控展示与可信证据 |
| 数据 | 真实用户与订单 | 演示数据 + 脱敏证据 |
| 访问 | 注册/登录用户 | 密码/受控邀请 |
| 路由 | 普通首页与产品路由 | 独立 `/showcase` 子站 |
| AI 调用 | 真实生产调用 | 受控演示调用 + 审计回放 |
| 生命周期 | 长期在线 | 比赛/评审周期内可开可关 |

### 1.3 文档目标

本规范用于约束 `/showcase` 子站的能力边界、可信证据生成机制、访问控制、AI 演示闭环、隐私与安全要求、内容真实性标记以及任务优先级与验收标准，确保：

1. 任何对外展示都基于真实生产代码与真实证据；
2. 任何展示内容都不得伪造产品能力、收入、客户或成功调用；
3. 任何演示调用都进入审计日志，可被管理员复核与回放；
4. 比赛结束后可保留代码与审计证据，但默认关闭外部访问；
5. 普通用户首页、产品导航不得出现比赛入口，避免污染产品体验。

## 3. 三类受众模式

`/showcase` 同时承担评委、投资人、政府园区三类外部受众的展示任务，每类受众有独立的角色视图、章节顺序与可信证据侧重。

### 3.1 评委模式（`/showcase/judge`）

- 受众：TRAE 比赛评委、技术评审、阶段性验收人。
- 目标：证明真实完成度、真实交互、真实证据。
- 必含模块：
  - 产品定位与真实用户场景；
  - 真实完成度对照表（按能力维度逐一标注状态）；
  - 真实交互演示（基于受控演示账号）；
  - 真实代码与 Prisma 模型证据；
  - 真实生产运维与数据治理证据；
  - AI 调用审计回放证据；
  - 评委专用展示章节（由 `ShowcaseContent` + `ShowcaseSequence` 管理）。
- 红线：不得把规划能力写成已上线；不得伪造调用成功；不得伪造客户线索。

### 3.2 投资人模式（`/showcase/investor`）

- 受众：投资人、FA、战略合作方。
- 目标：展示商业闭环、增长、成本、收费与可复制性。
- 必含模块：
  - 商业闭环：用户→名片→会员→支付→AI 调用→线索→复购；
  - 真实收入证据（脱敏聚合，不含个人数据）；
  - 真实会员与收费档位；
  - 真实 AI 成本与用量（脱敏聚合）；
  - 增长指标定义与计算口径；
  - 可复制性与扩张路径；
  - 投资人专用展示章节。
- 红线：不得把测试订单写成真实收入；不得把演示数据写成真实增长；不得展示真实用户隐私。

### 3.3 政府园区模式（`/showcase/government`）

- 受众：政府园区、产业主管部门、合规审计方。
- 目标：展示合规、审计、产业价值与中小企业服务能力。
- 必含模块：
  - 合规与审计能力（数据治理、留痕、可追溯）；
  - 产业价值与中小企业服务能力；
  - 真实名片数据治理与公开信息合规；
  - AI 调用安全策略与敏感内容拒答；
  - 审计日志与回放能力；
  - 政府园区专用展示章节。
- 红线：不得展示真实用户隐私；不得展示真实密钥或数据库连接；不得把规划能力写成已上线。

## 4. 可信演示闭环设计

可信演示闭环要求每一次对外演示都形成可追溯的完整链路。任何一环缺失即视为不可信演示，须触发降级展示。

### 4.1 闭环主流程

1. 谁访问（访问者身份标识、来源渠道、访问会话 ID）；
2. 访问哪个展示角色和版本（judge / investor / government，章节内容版本）；
3. 查看哪些模块（章节顺序由 `ShowcaseSequence` 决定，章节内容由 `ShowcaseContent` 决定）；
4. 发起什么 AI 问题（演示问题输入，受控额度内）；
5. 使用哪个已发布 Prompt 版本（由 `ShowcasePromptDraft` 发布版本决定）；
6. 使用哪个知识资料快照（由 `CompetitionFile` 版本或快照决定）；
7. AI 返回什么结果（受控实时调用或审计回放结果）；
8. 是否触发安全拒答或转人工（敏感内容判定与降级路径）；
9. 是否留下线索（演示留资或联系入口）；
10. 调用是否写入审计日志（写入 `ShowcaseAIDemoCall` 与 `ShowcaseAIDebugLog`）；
11. 管理员是否可以复核和回放（`/jeepwork/competition-ai-debug` 与 `/jeepwork/competition-center`）。

### 4.2 闭环状态字段

- 访问会话 ID：`showcase_session_id`
- 展示角色：`role`（judge / investor / government）
- 展示内容版本：`content_version`
- Prompt 发布版本：`prompt_version`
- 知识资料版本或快照：`knowledge_snapshot_id`
- 来源渠道：`source`（direct / invite / qr / link）
- 留资结果：`lead_result`（none / captured / rejected）
- 审计记录：`audit_record_id`

### 4.3 闭环断点处理

- AI 无法调用时：展示降级状态，提示"演示调用不可用"，不得伪造回答；
- Prompt 未发布：禁止发起演示调用，提示管理员先发布 Prompt 版本；
- 知识资料未上传：禁止发起演示调用，提示管理员先上传或选择快照；
- 审计写入失败：调用视为失败，前端展示降级状态。

## 5. 访问状态

`/showcase` 的对外访问状态由 `/jeepwork/showcase` 统一管理，支持以下状态：

| 状态 | 含义 | 外部可访问 | 备注 |
| --- | --- | --- | --- |
| 关闭 | 默认状态，外部不可访问 | 否 | 代码保留，路由保留 |
| 密码保护开放 | 输入正确密码可访问 | 是（密码校验） | 须配合限流【待核验】 |
| 指定角色开放 | 仅评委/投资人/政府特定角色可访问 | 是（角色校验） | 不同角色不同密码或邀请码 |
| 公开演示开放 | 任意人均可访问 | 是 | 仅在比赛/评审关键节点启用 |
| 维护中 | 短期不可访问，展示维护提示 | 否 | 仅管理员可后台访问 |
| 已结束归档 | 比赛结束后归档，外部不可访问 | 否 | 保留代码与审计证据 |

### 5.1 默认策略

- 非比赛/评审期间：默认关闭；
- 比赛/评审期间：密码保护开放或指定角色开放；
- 评审关键演示：公开演示开放（限时）；
- 比赛结束：默认切换为已结束归档。

### 5.2 限流与爆破防护【待核验】

- Showcase 密码登录需补充限流：同一 IP 单位时间失败次数限制；
- 密码尝试锁定：连续失败 N 次后临时锁定；
- 邀请码一次性使用：邀请码绑定访问会话 ID，使用后失效或标记已用；
- 此项标记为【待核验】，须由 Agent F 与运维团队确认是否已实现，否则列为 P1 补齐。

## 6. AI 演示两种模式

`/showcase` 的 AI 演示严格区分两种模式，二者均不可伪造结果。

### 6.1 受控实时调用模式

- 使用隔离的演示账号、演示知识库与受控额度；
- 调用真实 Provider 与真实模型（与生产环境一致的 Provider，但使用演示 Key 或限额）；
- 每次调用写入 `ShowcaseAIDemoCall` 与 `ShowcaseAIDebugLog`；
- 演示账号不得访问真实用户数据与真实客户线索；
- 受控额度耗尽后必须降级，不得伪造回答；
- 演示问题输入受安全策略约束，敏感内容触发拒答或转人工。

### 6.2 审计回放模式

- 展示历史已脱敏调用的输入、输出、Prompt 版本、知识版本、耗时、用量、成本估算与结果；
- 回放数据来自 `ShowcaseAIDemoCall` 与 `ShowcaseAIDebugLog`；
- 回放必须显示调用时间、Prompt 发布版本、知识资料快照版本；
- 回放不得修改原调用记录，仅可读取；
- 回放用于评委/投资人/政府园区在不发起实时调用时查看历史证据。

### 6.3 降级状态展示

不能调用时必须明确展示降级状态：

- 提示"演示调用暂时不可用"；
- 提示"演示额度已用尽，请使用审计回放查看历史证据"；
- 提示"Prompt 未发布或知识资料未就绪"；
- 严禁在降级状态下伪造回答、伪造成功调用或伪造结果。

## 7. 演示调用必须记录的字段

每次演示调用（无论成功或失败）必须完整记录以下字段至 `ShowcaseAIDemoCall` 与 `ShowcaseAIDebugLog`：

| 字段 | 说明 |
| --- | --- |
| 访问会话 ID | `showcase_session_id`，贯穿整个访问链路 |
| 展示角色 | judge / investor / government |
| 来源渠道 | direct / invite / qr / link |
| 展示内容版本 | `content_version` |
| Prompt 发布版本 | `prompt_version` |
| 知识资料版本或快照 | `knowledge_snapshot_id` |
| Provider 与模型标识 | 如 `openai/gpt-4o`、`doubao/...`、`deepseek/...` |
| 调用时间 | `called_at`，精确到毫秒 |
| 耗时 | `duration_ms` |
| Token 或用量 | `prompt_tokens` / `completion_tokens` / `total_tokens` 或对应用量 |
| 成本估算 | `estimated_cost`，按当前 Provider 计价估算 |
| 输入输出摘要或脱敏记录 | `input_summary` / `output_summary`，敏感字段脱敏 |
| 安全与敏感内容结果 | `safety_result`（pass / reject / transfer_to_human） |
| 错误码 | `error_code`，无错误为 null |
| 降级结果 | `degraded`（true / false） |
| 留资结果 | `lead_result`（none / captured / rejected） |
| 访问日志 | `access_log_id`，关联访问日志 |
| 管理员审计记录 | `audit_record_id`，关联管理员复核记录 |

字段缺失即视为演示闭环不完整，调用应标记为 `degraded=true` 并触发降级展示。

## 8. 隐私与安全要求

### 8.1 数据隔离

- 演示数据与真实用户数据严格隔离；
- 使用独立演示工作空间或演示账号；
- 演示知识库与生产知识库物理或逻辑隔离；
- 演示调用不得访问真实用户表、真实订单表、真实客户线索表。

### 8.2 敏感信息禁止展示

- 不得展示真实 API Key、Secret、Token；
- 不得展示生产数据库连接字符串；
- 不得展示真实用户姓名、手机号、邮箱、身份证、地址；
- 不得展示真实支付凭证中的个人字段；
- 不得展示真实客户线索中的企业联系人隐私字段。

### 8.3 真实性约束

- 不得把测试订单写成真实收入；
- 不得把规划能力写成已上线；
- 不得伪造成功调用；
- 不得伪造客户线索；
- 不得伪造增长数据；
- 可以使用演示数据，但必须明确标注"演示数据"。

### 8.4 安全策略

- 演示问题输入受安全策略约束；
- 敏感内容触发拒答或转人工；
- 演示账号受控额度，超额即降级；
- 所有演示调用写入审计日志，可被管理员复核与回放；
- 密码登录须配合限流与爆破防护【待核验】。

## 9. 展示内容真实性标记

`/showcase` 中每一个对外展示的能力点必须标注以下标记之一，未标注的能力不得上线展示：

| 标记 | 含义 |
| --- | --- |
| 【已上线】 | 已在生产环境真实运行，可对外承诺 |
| 【内测中】 | 已在内部测试，仅向特定受众披露 |
| 【本次改版】 | 本次比赛/评审周期内完成的改版能力 |
| 【未来规划】 | 已规划但未实现，仅作方向展示 |
| 【演示数据】 | 数据为演示用途，非真实生产数据 |

### 9.1 标记使用规则

- 同一能力点只能标注一个主标记；
- 演示数据须叠加标注【演示数据】；
- 未来规划不得与已上线混用；
- 内测中能力不得在投资人模式中作为收入或增长证据；
- 标记由 `ShowcaseContent` 字段统一管理，前端按字段渲染。

## 10. 路由保留策略

### 10.1 路由保留原则

- `/showcase` 路由长期保留，不删除；
- 普通首页不提供 `/showcase` 明显入口；
- 普通导航不展示比赛按钮；
- 允许通过直接地址或受控流程访问；
- 开放状态由 `/jeepwork/showcase` 统一管理。

### 10.2 比赛结束后策略

- 比赛结束后默认关闭外部访问；
- 保留 `/showcase` 代码与路由；
- 保留 `ShowcaseAIDemoCall`、`ShowcaseAIDebugLog`、`ShowcasePromptDraft`、`CompetitionFile` 审计证据；
- 状态切换为"已结束归档"；
- 如有下一轮评审，可重新开放，但须重新发布 Prompt 版本与知识资料快照。

### 10.3 与产品本体的边界

- `/showcase` 不得反向污染普通首页与产品路由；
- 普通用户不得在产品内看到任何比赛/评审入口；
- 演示账号与真实用户账号体系隔离；
- 演示调用不得写入生产业务统计。

## 11. 任务优先级

### P0（必须完成，阻塞对外展示）

- P0-1：可信演示闭环完整性核验（访问会话 ID、Prompt 版本、知识快照、审计日志、回放）；
- P0-2：演示数据与真实用户数据隔离核验；
- P0-3：降级状态展示核验（不得伪造回答）；
- P0-4：真实性标记全量覆盖核验（无未标注能力点）；

### 12.2 可信闭环验收

- 任意一次演示调用均可追溯：访问者→角色→章节→Prompt 版本→知识快照→AI 结果→安全判定→审计日志→管理员回放；
- 任意一次调用失败或降级均有对应字段与提示；
- 任意一次调用均不得伪造结果。

### 12.3 隐私与安全验收

- 演示数据与真实用户数据隔离；
- 演示账号不得访问真实用户表；
- 不得展示真实 Key、数据库连接、用户隐私；
- 测试订单不得写成真实收入；
- 规划能力不得写成已上线；
- 演示数据必须标注"演示数据"。
