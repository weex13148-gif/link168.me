# Link168 当前产品主线

**版本：** SaaS Mainline v1（2026-07-18）
**状态：** 已确认，进入分阶段实施
**唯一权威规格：** `docs/superpowers/specs/2026-07-18-link168-saas-product-mainline-design.md`
**实施路线图：** `docs/superpowers/roadmaps/2026-07-18-link168-saas-mainline-program.md`

> Link168 当前只服务“专业商业名片 + 24 小时接待 + 真实 Lead + 轻量跟进”这一条经营闭环。本文只维护当前执行摘要；完整规则以唯一权威规格为准。

## Historical context

> 以下 MVP v2.1 内容仅保留为历史背景，非当前权威。

### MVP v2.1 执行范围

#### 1. MVP 一句话定义

> **Link168 MVP v2.1 = 用户能够在手机端创建并装修真实经营名片，添加产品、服务、图片和常用平台链接，发布后由访客查看、咨询或留资，AI 可以进行第一轮接待并在无法确认时转人工，商家能够查看、跟进并记录真实客户线索。**

MVP 的目标不是页面数量，也不是展示大量尚未闭环的功能，而是证明：

```text
经营内容可以创建
→ 名片可以发布
→ 访客可以理解业务
→ 客户可以咨询或留资
→ 商家可以跟进
→ 数据可以记录
```

---

#### 2. 当前 MVP 的唯一核心闭环

```text
注册与登录
→ 创建经营名片
→ 添加头像、背景、封面、产品、服务和联系方式
→ 添加微信、抖音、小红书等平台链接并显示对应 Logo
→ 手机预览
→ 保存并发布
→ 分享链接或二维码
→ 访客查看业务、点击、咨询或留资
→ AI 第一轮接待或转人工
→ 生成客户线索
→ 商家查看、标记和跟进
→ 标记已成交或已关闭
→ 查看访问、咨询、留资和转化数据
```

任何本轮开发事项必须位于上述闭环中。不能说明所在环节的功能，不进入本 MVP。

---

### 3. MVP 必须完成的能力

### 3.1 账号和公开状态

必须具备：

- 邮箱注册和登录；
- 基础密码安全；
- 用户名和公开地址；
- 名片草稿、已发布和已下线状态；
- 未发布内容不能公开；
- 冻结、封禁或按规则受限时公开页正确降级；
- 公开页举报入口；
- vCard 与公开隐私状态一致。

真实邮件验证码发送在管理员配置阿里云邮件推送前标记为“待配置测试”，不得伪造发送成功。

### 3.2 统一用户后台

普通用户长期只认一个用户控制台产品心智。

MVP 必须提供：

- 经营概览；
- 名片装修；
- 产品和服务；
- 客户线索；
- 基础数据；
- AI 接待及知识资料；
- 会员和账号入口。

旧 `/dashboard`、`/workbench/*` 可以保留兼容跳转，但不能继续作为多个并列后台发展。

手机端 360–430px 必须可操作，不得出现横向溢出、按钮不可点击、弹窗超屏或白字白框。

### 3.3 用户后台组件闭环

本轮必须收口：

- 普通链接；
- 文本和分组标题；
- 产品卡片；
- 服务卡片；
- 优惠活动；
- 预约；
- 报价咨询；
- 联系表单；
- 电话；
- 邮箱；
- 微信号；
- 地址；
- 已有图片、视频、FAQ 和 AI 入口兼容。

每一种组件只有同时满足以下条件才算完成：

1. 后台有中文添加入口；
2. 可以新增；
3. 可以编辑；
4. 可以保存；
5. 可以排序；
6. 可以隐藏和恢复；
7. 可以删除；
8. 刷新后数据仍存在；
9. 手机预览正确；
10. 公开页正确；
11. 权限和错误状态正确；
12. 联系或咨询组件能够产生真实 Lead。

仅存在数据库字段、接口、静态卡片或公开页渲染，不算组件闭环完成。

### 3.4 图片和媒体闭环

MVP 必须覆盖：

- 个人头像；
- 名片背景图；
- 顶部封面图；
- 图片轮播；
- 产品封面；
- 服务封面；
- 企业 Logo；
- 企业公开页需要的图片。

必须支持：

- 上传；
- 替换；
- 删除；
- 类型、大小和必要尺寸校验；
- 处理中和失败状态；
- 权限校验；
- 数据持久化；
- 旧文件处理规则；
- 手机预览与公开页一致。

真实对象存储或图片审核未配置时，只能验证页面、参数、权限、接口结构和安全失败，不得声称真实远程上传、删除或审核已经通过。

### 3.5 常用平台 Logo 与链接识别

这不是独立 Logo 资料库页面，而是链接组件的核心体验。

用户添加平台链接时必须支持：

- 根据 URL 自动识别平台；
- 手动搜索并选择平台 Logo；
- 选择自动识别、预设平台、自定义图标或通用图标；
- 保存后刷新仍然存在；
- 后台预览和公开页显示一致；
- 未识别平台使用通用链接图标；
- 继续兼容旧 Emoji 和自定义图标数据。

首批至少包括：

- 微信、企业微信、QQ、微信号；
- 抖音、小红书、快手、微博、哔哩哔哩、知乎；
- 淘宝、天猫、京东、拼多多、闲鱼；
- 美团、大众点评；
- 支付宝；
- 高德地图、百度地图；
- 钉钉、飞书；
- GitHub、Gitee；
- 电话、邮箱、地址和通用网站。

平台定义优先采用统一代码配置和本地静态资源：

```ts
type PlatformDefinition = {
  key: string;
  name: string;
  aliases: string[];
  domains: string[];
  iconPath: string;
  enabled: boolean;
  sortOrder: number;
};
```

优先复用现有字段保存：

```text
iconType = platform
iconValue = douyin
```

能够安全复用现有字段时不强制新增 Prisma 字段。

图标优先级：

```text
用户明确手动选择
→ 用户自定义上传
→ 自动域名识别
→ 网站 favicon
→ 通用链接图标
```

只有处于“自动识别”模式时，修改 URL 才能自动改变平台；不得覆盖用户已经手动选定的图标。

不得使用容易失效的第三方图片热链，也不得通过平台 Logo 暗示官方合作或认证。

### 3.6 产品和服务

用户必须能够：

- 创建、编辑和下架产品与服务；
- 设置名称、简介、价格说明、封面、行动按钮和公开状态；
- 将产品和服务添加到公开名片；
- 让访客发起咨询；
- 在 Lead 中保留来源产品或服务快照；
- 产品下架后仍保留历史 Lead 的原始信息。

### 3.7 AI Provider 和安全降级

MVP 的 AI 采用两层结构：

```text
业务层：用户、Workspace、公开资料、权限、知识库、Lead、转人工和审计
模型层：阿里百炼 Provider、未来备用 Provider
```

必须满足：

- 模型名称、App ID、接口地址和额度不散落写死；
- Link168 Workspace ID 与 DashScope Workspace ID 明确区分；
- 百炼未配置、超时、限流或不可用时，公开名片仍正常展示；
- 产品、服务、联系方式和联系表单仍可使用；
- AI 不可用时返回真实状态，不伪造回答；
- 公开资料、内部资料和禁止资料明确隔离。

本轮在老板配置 API 前只测试 Provider 接口、权限、参数、错误转换、Mock 和安全降级，不测试真实百炼回答。

### 3.8 转人工与 Lead 闭环

出现以下情况时必须转人工：

- AI 无法从公开资料确认；
- 客户要求正式报价；
- 涉及定制服务；
- 涉及合同、退款、售后或投诉；
- 涉及高风险行业问题；
- 客户明确要求本人联系。

转人工必须生成结构化线索，至少记录：

- 客户关注内容；
- 主要问题；
- 联系方式；
- 是否要求本人联系；
- 来源页面和组件；
- 来源产品或服务快照；
- AI 对话摘要；
- 推荐跟进动作。

Lead 状态统一为：

```text
新线索
→ 已查看
→ 跟进中
→ 已成交 / 已关闭
```

当前 MVP 不建设完整 CRM，不增加复杂销售阶段、审批和自动化营销。

### 3.9 四类核心经营指标

MVP 只收口四类指标：

1. 访问；
2. 咨询；
3. 留资；
4. 转化。

要求：

- 来自真实服务端事件；
- 有必要的去重或幂等规则；
- 用户只能查看自己的聚合数据；
- 企业只能查看本 Workspace；
- 不使用随机数和演示数据冒充真实统计；
- 不为了增加图表重复制造无经营价值的埋点。

### 3.10 社媒 Agent 人工确认

MVP 中社媒 Agent 可以：

- 生成内容；
- 生成标题和选题；
- 生成不同平台版本；
- 给出发布时间和素材建议；
- 保存待发布草稿。

MVP 中社媒 Agent 不可以：

- 未经用户确认自动登录平台；
- 未经逐次确认自动发布；
- 自动群发；
- 使用未授权素材；
- 把生成草稿写成已经发布。

本轮不接入真实抖音、小红书等发布 API。

### 4. MVP 必须同时修复的安全阻断

### 4.1 平台权限只保留 super_admin

平台级最高权限只保留：

```text
super_admin
```

必须专项清理和验证：

- 平台普通 `admin` 角色；
- `role === "admin"`；
- `["admin", "super_admin"]`；
- `/admin` 动态路由；
- admin 会员、订单、用户和系统配置权限；
- 管理员初始化和会话逻辑。

企业管理员可以保留，但必须明确属于企业 Workspace，不得与平台 `admin` 混淆。

### 4.2 D2 企业域名和企业名片

D2 在以下问题解决前不得合并或部署：

- 套餐权益只从服务端真实 Workspace 读取；
- 并发绑定不能突破数量限制；
- `/__w/[workspaceId]` 必须验证真实请求 Host；
- 存在 `NEXT_PUBLIC_APP_URL` 时也不能跳过 Host 校验；
- Host 必须对应 verified Domain 和同一 Workspace；
- 未知或不匹配 Host 返回 404；
- canonical、JSON-LD、分享和举报地址使用真实企业 Host；
- 普通成员只能读取自己的员工名片；
- 企业 Workspace 数据隔离必须经过独立验证。

### 4.3 D4 企业 AI 额度

D4 在以下问题解决前不得合并或部署：

- 空 `workspaceId` 在数据库查询前返回错误；
- 企业成员使用企业 AI 不依赖个人套餐；
- 企业路由只扣企业共享额度；
- 幂等 key 防止重试重复扣减；
- reserve、confirm 和 refund 使用原子条件状态转换；
- confirm 和 refund 并发不能互相覆盖；
- 退款文案必须反映真实结果；
- 退款失败不得显示“已退回”；
- confirm 失败不得返回普通 AI 成功；
- 删除重复代码；
- 更新旧 boolean 测试；
- 真实 PostgreSQL 并发未执行时必须标记“尚未验证”。

### 4.4 公开 AI 权益

公开名片 AI 入口必须同时满足：

- 名片主人具有有效 AI 权益；
- 名片主人已主动启用访客 AI；
- AI Provider 配置有效；
- 当前名片允许公开；
- 额度和风险规则允许调用。

不得对所有公开名片无条件显示或开放真实 AI 接待。

### 4.5 套餐和价格一致性

套餐展示、购买入口、服务端白名单和权益配置必须一致。

不得出现：

- 页面展示一个套餐，服务端允许购买另一个套餐；
- Plus 已定义但公开页面只展示 Pro；
- 前端价格与订单快照不一致；
- 未交付的企业能力宣传为已经上线。

具体价格由正式套餐配置决定，不在本 MVP 文件中重新写死。

### 6. 方案 C：两批五 Agent 开发

采用以下顺序：

```text
第一轮 5 个 Agent
→ 第一轮总控集成和门禁
→ 第二轮 5 个 Agent
→ 最终总控集成和修复
→ GitHub 独立复审
→ 老板决定是否合并
```

### 6.1 第一轮：基础与高风险

1. 共享数据合同和兼容规则；
2. D2 企业域名安全；
3. D4 企业 AI 额度安全；
4. 图片与媒体底层；
5. 常用平台 Logo 和链接识别。

第一轮未通过门禁，不启动第二轮。

### 6.2 第二轮：用户业务闭环

6. 组件后端 CRUD 和权限；
7. 组件编辑器、手机预览和公开渲染；
8. AI Provider 和安全降级；
9. 转人工与 Lead 闭环；
10. 四类经营指标和社媒人工确认。

### 6.3 总控 Agent 边界

总控 Agent 只负责：

- 按固定顺序集成；
- 解决接口接线；
- 修复编译和测试错误；
- 删除重复代码；
- 修复集成回归；
- 统一命名和渲染。

总控 Agent 不得：

- 改变产品方向；
- 增加新功能；
- 重写产品宪法或 PRD；
- 直接合并 `master`；
- 进入服务器；
- 自己开发、自己复审并直接宣布通过。

### 8. MVP 明确不做

当前 MVP 不包括：

- 完整 CRM；
- ERP、进销存和财务系统；
- 大型 OA 和审批流；
- 自动群发和私域骚扰营销；
- 自动跨平台社媒发布；
- 复杂 Logo 管理后台；
- 大型模板交易市场；
- 无边界的企业管理系统；
- 未验证的全量第三方系统集成；
- 新增与核心闭环无关的装修组件；
- 扩展 `/showcase`；
- 为了收口删除支付、AI、邮件、会员、企业、`/showcase` 或 `/jeepwork` 的未来结构。

“找 3–5 个真实商家跑成交链路”属于 MVP 上线后的真实试运营验收，不允许 Agent 用 Mock、测试数据或文字汇报冒充完成。

### 9. MVP 完成标准

MVP 只有同时满足以下条件才可以标记为完成：

1. 产品宪法、PRD 和本 MVP 文件没有互相冲突；
2. 两批 Agent 的范围全部有可追溯提交；
3. 所有 Agent 遵守文件所有权，没有并行覆盖；
4. 总控 Agent 只进行集成和修复；
5. 干净环境 `npm ci` 成功；
6. Prisma validate 和 generate 成功；
7. Lint、TypeScript、统一测试和生产构建成功；
8. 最小 GitHub CI 有可验证结果；
9. `super_admin` 边界通过专项测试；
10. D2 Host 和 Workspace 隔离通过；
11. D4 幂等、confirm/refund 和真实 PostgreSQL 并发通过；
12. 组件新增、编辑、排序、隐藏、恢复和删除通过；
13. 图片上传、替换、删除或未配置安全失败通过；
14. 抖音链接能够显示抖音 Logo，并在刷新、手机预览和公开页中保持一致；
15. AI Provider 未配置时不会影响名片和人工联系；
16. AI 转人工能够形成真实 Lead；
17. Lead 可以完成新线索、已查看、跟进中、已成交/已关闭流转；
18. 访问、咨询、留资和转化来自真实事件；
19. 公开 AI 入口受到服务端权益和启用状态控制；
20. 套餐展示、购买白名单和订单快照一致；
21. 没有已知 P0 阻断、重复代码或未提交改动；
22. 外部 API 未测试项被真实标记；
23. GitHub 最终代码经过独立复审；
24. 老板明确批准后才进入合并和服务器阶段。

以下任一情况存在时，不得写“新版 MVP 已完成”“建议部署”或“可以上线”：

- CI 没有结果；
- 核心测试失败；
- 普通平台 `admin` 尚未清理；
- Workspace 隔离未验证；
- D2 或 D4 仍有阻断；
- 真实 PostgreSQL 并发未验证；
- 退款失败却显示已退款；
- 外部 API 未配置却声称真实测试通过；
- 后台预览和公开页不一致；
- 手机端核心操作不可用。

### 10. MVP 上线后的第一轮真实验证

完成代码、复审和基础部署后，再选择 3–5 个真实创业者或小商家进行试运营：

1. 发布真实经营名片；
2. 上传真实产品或服务；
3. 添加微信、抖音或小红书等真实链接；
4. 让真实访客查看和咨询；
5. 留下一条真实需求；
6. 商家进行人工跟进；
7. 记录是否产生有效线索或成交。

第一阶段最重要的经营指标不是注册用户总数，而是：

> **有多少用户通过 Link168 获得了第一条有效客户线索。**

---

### 11. 本版本变更摘要

相对旧 MVP，本次新增或提升为必须项：

1. 用户后台组件必须形成真实 CRUD 和公开展示闭环；
2. 头像、背景、封面、轮播、产品图片和企业 Logo 形成媒体闭环；
3. 抖音、小红书等常用平台链接必须提供真实平台 Logo；
4. AI Provider 可替换并支持不可用降级；
5. AI 无法确认、报价、合同、退款和售后场景转人工；
6. Lead 状态统一；
7. 核心指标统一为访问、咨询、留资和转化；
8. 社媒 Agent 发布必须人工确认；
9. 平台级普通 `admin` 必须清理，只保留 `super_admin`；
10. D2 和 D4 安全阻断纳入 MVP 必须修复项；
11. 建立最小 CI 和统一测试入口；
12. 明确 `master`、文档分支、D2/D4 分支和最终集成分支的关系；
13. 未配置的百炼、邮件、支付宝和存储功能暂不进行真实测试；
14. 采用两批五 Agent 的方案 C，不再让 10 个 Agent 同时自由修改相邻模块。
