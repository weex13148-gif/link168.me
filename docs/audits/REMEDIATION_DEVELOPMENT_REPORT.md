## 2. 当前V2正式范围

V2核心闭环：

```text
邮箱注册和登录
→ 创建经营名片
→ 发布和分享
→ 访客访问与留资
→ 客户跟进
→ 数据分析
→ 会员和支付宝
→ AI经营能力
→ 企业空间与站内成员管理
```

当前正式边界：

- V2只开放邮箱注册和登录。
- 普通微信注册、登录和绑定退出V2。
- 企业微信、飞书和钉钉连接退出V2。
- 企业成员采用Link168站内邮箱邀请。
- 账号合并、最后登录身份解绑、多平台成员去重暂不处理。
- 企业管理员不能查看成员AI对话正文。
- 已有未来代码和数据结构保留、隐藏或关闭，不因暂缓而删除。

## 4. 当前开发任务：A 邮箱身份闭环

### 4.1 任务目标

在不修改Prisma Schema、不新增第三方依赖的前提下，加固现有邮箱认证能力：

- 邮箱注册和密码登录。
- 邮箱验证码和重新发送。
- 注册满30天仍未验证时允许登录后台，但公开名片和敏感写入受限。
- 邮箱验证成功后只解除邮箱未验证限制。
- 忘记密码和一次性重置链接。
- 重置密码后撤销全部旧Session。
- 登录失败限流和真实登录结果记录。
- Session创建失败时不伪造登录成功。

## 5. 第一批已完成代码

### AUTH-01 邮箱验证30天边界

**状态：代码已实现，待完整仓库验证**

- 新增统一的30天宽限期计算。
- 注册时间达到30天时进入邮箱未验证限制，不再延迟到第31天。
- 未验证限制不阻止登录后台。
- `EMAIL_UNVERIFIED`仍由服务端阻止公开展示和要求活跃账号的敏感写入。

### AUTH-02 验证码按用户隔离

**状态：代码已实现，策略测试通过**

- 新验证码哈希使用`User ID + 6位验证码`。
- 相同验证码在不同用户之间不会产生相同数据库哈希。
- 验证时同时兼容部署前已经发出的旧验证码。
- 6位验证码必须与当前登录用户匹配。
- 邮件服务失败时将本次验证码作废，不伪造发送成功。

### AUTH-03 邮箱验证原子消费

**状态：代码已实现，待数据库并发集成验证**

- 验证凭证在事务中领取。
- 同一凭证只能有一次更新成功。
- 验证成功、用户邮箱状态更新、邮箱限制解除和其他未使用验证码失效在同一事务中完成。
- 管理员冻结、封禁和安全风险限制不会被邮箱验证解除。

### AUTH-04 密码重置原子消费

**状态：代码已实现，待数据库并发集成验证**

- 重置令牌在事务中一次性领取。
- 修改密码、撤销旧Session和作废其他重置令牌在同一事务中完成。
- 同一重置链接并发提交时只允许一次成功。
- 成功文案明确所有旧设备已经退出。

### AUTH-05 登录成功审计

**状态：代码已实现，待完整流程验证**

- 账号限制查询成功后才继续建立Session。
- Session真正创建成功后才记录登录成功。
- Session创建失败返回真实503错误，不记录成功。
- 登录成功日志写入失败不反向破坏已建立的正常登录。

### AUTH-06 注册后Session失败处理

**状态：代码已实现，待完整流程验证**

- 用户和个人空间创建成功但Session创建失败时，返回明确恢复路径。
- 不向前端伪造已登录状态。
- 用户可返回登录页使用已创建的邮箱账号登录。

## 7. A主线剩余工作

### 必须完成

1. 在正式本地工作区或可执行CI中运行`npm ci`。
2. 运行Prisma Client生成和Schema校验。
3. 运行`npm run test:auth`。
4. 运行`npm run lint`。
5. 运行`npm run typecheck`。
6. 运行生产`npm run build`。
7. 使用测试数据库验证同一验证码并发提交只成功一次。
8. 使用测试数据库验证同一重置链接并发提交只成功一次。
9. 验证注册29天、满30天和超过30天三个账号状态。
10. 验证邮箱成功后只解除`EMAIL_UNVERIFIED`，不解除其他限制。
11. 验证重置密码后所有旧Session失效。

### 发现问题时的处理原则

- 只修复A主线文件锁范围内的问题。
- 不为通过测试删除业务能力。
- 不修改Prisma Schema，除非先提交影响分析并由老板批准。
- 不接入微信、企业微信、飞书或钉钉。
- 不触碰生产服务器和真实密钥。
