## 三、与产品宪法的主要冲突

### P0-1：工程规则优先级错误

现有 `PROJECT_RULES.md` 把自己写成最高优先级，高于PRD和产品规则，与产品宪法明确的优先级冲突。

必须改成：

```text
老板 → 产品宪法 → PRD → PROJECT_RULES → 代码事实
```

### P0-2：五档套餐没有统一

产品宪法固定：免费版、Plus、Pro、企业版、企业Pro。

当前代码同时存在：

- free
- plus
- member_basic
- member_plus
- pro
- enterprise
- enterprise_pro_plus
- internal_test

公开首页只展示四档，没有企业Pro。旧别名和内部测试档不能继续混入正式业务判断。

当前代码价格同样与老板于2026-07-10批准的正式定价冲突：Plus 188元/年、Pro 388元/年、企业版1280元/年、企业专业档2680元/年均属于旧实现。唯一正式目标为 Plus 69元/月或599元/年、Pro 139元/月或999元/年、企业版8800元/年、企业Pro 19800元/年；不设创始价。代码价格必须整改，不能反向写入PRD。

### P0-3：统一控制台尚未完成

`/console` 已存在，但其内部仍跳转：

- `/dashboard`
- `/workbench/products`
- `/workbench/leads`
- `/workbench/analytics`
- `/workbench/ai`
- `/workbench/membership`

共享导航说明三套Shell共同读取，这证明当前只是增加了控制台外壳，并未真正合并用户后台。

### P0-4：普通用户导航暴露Jeepwork入口

共享用户导航把 `/jeepwork` 标记为 `live` 管理后台入口。即使后端有鉴权，也不应在普通用户控制台固定展示平台管理入口。

### P0-5：付费去品牌权益未落实到公开页

套餐配置中Plus及以上包含 `removeBranding: true`，但公开页当前固定传入 `showBrandFoot={true}`，会始终展示“由Link168提供”。

需要服务端读取用户权益后决定品牌展示。

### P0-6：检查时旧PRD仍是四档旧口径（已由本次PRD替换）

检查时旧PRD权益表只有免费、Plus、Pro、企业版四档，且写有免费AI“体验或关闭”。本次已替换为五档正式结构，并明确免费版不赠送套餐内AI额度，但所有用户均可购买AI加量包。

### P1-1：数据库仍保留比赛/Showcase模型

代码取舍清单声称展示中心不进入V2主分支，但 `schema.prisma` 仍包含：

- CompetitionFile
- ShowcaseContent
- ShowcaseSequence
- ShowcaseAIDemoCall
- ShowcaseAIDebugLog
- ShowcasePromptDraft

这不代表必须立即删除；它说明“活动产品线已移除”和“数据库历史结构仍保留”需要在文档中明确区分。

### P1-2：套餐显示和内部映射有旧名称

`/console` 的会员名称映射仍使用 `starter` 等旧代码，缺少Plus和企业Pro的完整显示逻辑。

### P1-3：AI失败回补来源需要复核

当前回补逻辑存在简化处理。若原消费来自套餐额度，失败后不应错误增加现金购买Credit余额。需要记录原扣减来源并按原来源回补。

### P1-4：公开留资限流仅为进程内内存

当前 `/api/contact` 的频率限制和重复提交缓存使用内存Map，进程重启会丢失，多实例之间不共享。当前单实例可暂用，但生产增长后应迁移到Redis或数据库级限流。

### P1-5：免费用户AI规则与最新商业决策冲突

旧PRD和部分代码把免费用户写成“禁止购买AI加量包”。老板于2026-07-10已明确：所有用户均可购买AI加量包。正确规则是免费版不赠送AI额度、不自带六大Agent，但购买有效加量包后可按SKU范围使用对应AI能力。需要同步修改前端入口、订单SKU、服务端权限、额度账本和过期规则。

### P1-6：推广员审核与邮件通知尚未闭环

免费版、Plus、Pro均可申请推广员，必须由管理员审核，并对通过或拒绝结果发送邮件。目前仓库未形成完整申请、审核、通知、订单归属、佣金和退款撤销闭环。

### P1-7：依赖版本使用`latest`

`package.json` 中Next.js、React、TypeScript、ESLint等使用 `latest`。虽然lock文件可暂时固定安装结果，但重装或更新lock时存在不可控升级风险。正式版本应固定明确版本范围。
