# 下一批建议

## 建议目标

继续整改现有仓库，启动“核心闭环与租户边界收口”批次，不做全量重写。

## 允许修改范围

- 统一 `/console` 为普通用户主入口；旧 `/workbench`、`/dashboard` 仅保留受控兼容跳转。
- 补齐服务端 Workspace 归属校验，明确个人 Workspace 与企业 Workspace 的数据 owner。
- 修复 `enterprise_pro` 域名权益判断，补 D2 Host、跨 Workspace、成员权限攻击用例。
- 在隔离 PostgreSQL 验证企业 AI 额度 reserve/confirm/refund 并发和幂等。
- 统一 Lead 新状态的服务端写入与统计口径，保留历史状态只读兼容。
- 为公开页→咨询→Lead→跟进→访问/咨询/留资/转化补浏览器或服务端端到端验收。

## 禁止修改范围

- 不删除支付、会员、AI、邮件、企业或 `/jeepwork`。
- 不恢复或重建 `/showcase`；不破坏性删除历史 Showcase 表。
- 不新增第二套订单、额度账本、后台或 CRM。
- 不接真实社媒自动发布，不在未配置时调用真实百炼、邮件、支付宝、对象存储。
- 不修改 Git 历史，不切换或清理用户既有改动，不直接操作生产。

## 依赖与风险

1. 需要明确 Workspace 数据迁移/兼容读取方案，否则任何企业能力扩展都会继续扩大边界风险。
2. 需要隔离 PostgreSQL 才能验证 D4；没有该环境时必须标记“真实数据库并发尚未验证”。
3. 需要明确的测试账号和独立复审，不能仅依赖当前 Jest 通过。
4. D2 需要真实域名、Nginx/Host、HTTPS 服务器测试；未完成前不得部署企业域名能力。
5. 外部服务需要老板在受控配置中心完成配置，不能在报告或代码中写入密钥。

## 验收条件

- 单一主入口导航不再出现重复后台心智，旧入口仅兼容跳转。
- 企业 A 无法读取或修改企业 B 的 Workspace、成员、公开名片、Lead、知识库和额度。
- `enterprise_pro` 按正式合同获得正确域名和 AI 共享额度权益，旧别名只用于兼容历史数据。
- 同一幂等键不会重复预占/确认/退款；失败只在真实退款成功后显示已退回。
- Lead 状态服务端单一写入，跟进历史独立记录，四类指标来自真实事件。
- `prisma validate`、`generate`、lint、typecheck、Jest、build、diff check 通过，并补齐隔离库/浏览器证据。
- 外部 API 未验证项逐项标为“待配置验证”或“待服务器测试”。

## 是否应先修阻断问题

是。先修租户边界、D2、D4、后台入口和真实验收门禁，再处理视觉细节或新增套餐能力。

## 是否建议重建后台外壳

建议做有限的外壳收口，不建议重建业务底座：复用现有 Profile、Product、Lead、AI、订单、额度和 Workspace 服务；只统一导航、数据归属和页面调用，避免出现第三套逻辑。
