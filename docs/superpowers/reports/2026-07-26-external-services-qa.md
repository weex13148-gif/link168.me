# Link168 外部服务验收记录

日期：2026-07-26
范围：AI（百炼/OpenAI 兼容接口）、SMTP 邮件、支付宝

## 当前结论

- 生产站点 `https://link168.me/api/health` 返回 HTTP 200，应用与数据库可访问。
- 本地测试数据库的 `app_configs` 为空；真实服务密钥不在本地环境中，符合“不把生产密钥落入开发仓库”的原则。
- AI、邮件和支付宝均已有超级管理员专用的真实测试入口，并且不会用“字段已填写”冒充“连接已通过”。
- 本轮补强了两个通过条件：
  - AI 必须收到 HTTP 200 且包含非空的真实 completion，才记录为通过。
  - SMTP 必须先完成连接验证、再成功发信，并确认测试收件人被 SMTP 服务器接受，才记录为通过。
- 支付宝本地 RSA2 验钥只记录诊断，不会生成绿色就绪证据；只有真实查单响应完成验签后才能记录为通过。

## 自动化验证

新增 `tests/external-service-test-routes.test.ts`，覆盖：

1. AI 测试入口必须经过超级管理员鉴权。
2. AI 只有真实 completion 响应才能通过。
3. HTTP 200 但 completion 为空时记录失败。
4. 邮件只有 SMTP 验证、发信、收件人接受全部完成时才通过。
5. 收件人未被 SMTP 接受时记录失败。
6. 支付宝本地验钥不会形成外部服务通过证据。
7. 支付宝真实查单响应验签通过后才形成通过证据。
8. 未获得验签证据的查单不能形成绿色状态。

## 仍待生产环境验证

以下项目必须在已登录的生产超级管理员页面中执行，当前不能仅根据“API 已配置”标记为通过：

- AI：执行一次最小真实连接测试，会产生一次服务调用和少量额度消耗。
- 邮件：向指定测试邮箱发送一封真实测试邮件。
- 支付宝：优先查询一笔专用测试订单并验证支付宝响应签名；如没有可用订单，再创建一笔不付款的测试订单。

完成以上三项后，应在管理端确认对应服务状态为“已配置并通过”，并保留检查时间、配置指纹和脱敏结果；不得保存或展示密钥原文。
