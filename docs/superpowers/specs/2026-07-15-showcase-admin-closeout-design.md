**日期：** 2026-07-15  
**目标分支：** `codex/showcase-admin-closeout-20260715`  
**基线：** `master`

## 1. 目标

在不扩张产品范围、不触碰生产服务器和生产数据库的前提下，完成两项发布前收口：

1. 修正 `/showcase` 的过期、占位和状态误导内容，使比赛展示与当前 MVP 真实边界一致；
2. 收口 `/jeepwork` 的比赛入口与历史 `admin` 角色入口，继续保持平台后台仅允许 `super_admin`。

## 2. 明确不做

- 不部署服务器；
- 不修改生产数据库；
- 不调用阿里百炼、阿里云邮件、支付宝或对象存储生产服务；
- 不重构完整 Jeepwork；
- 不删除历史 `admin` 数据；
- 不删除 `/showcase`；
- 不扩展新的产品功能；
- 不将尚未真实验证的外部能力描述为已上线。

## 4. Showcase 内容状态模型

所有能力统一按真实证据展示：

- `completed`：代码闭环和自动测试已通过，且不依赖未验证的生产外部服务；
- `pending_validation`：代码已接入，但仍待生产配置或真实服务验证；
- `beta`：可演示或内测，尚未作为正式稳定能力开放；
- `planned`：下一阶段能力。

禁止将“代码已存在”直接写成“生产服务已可用”。

当前边界：

- 注册、登录、名片编辑、公开主页、组件 CRUD、Lead、基础分析、Jeepwork 权限与治理：代码和自动测试已通过；
- 阿里百炼、阿里云邮件、支付宝、对象存储、真实企业域名、生产服务器与生产数据库：待生产配置验证；
- 正式支付、真实退款、会员自动到期降级：不得宣传为已正式上线。

## 5. Showcase 页面改动

### 5.1 删除旧占位

删除或替换：

- `未备案`；
- `待补充主体名称`；
- `待补充`；
- `项目负责人`；
- `demo` 演示账号；
- `每日重置数据`；
- 未经证据支持的“沙箱已验证”“正式支付已完成”等描述。

### 5.2 访问控制

- 仅使用共享密码，不提供演示账号；
- 成功验证后当前设备长期保持访问权限，直到用户清除浏览器数据；
- 后台修改共享密码后，所有旧设备立即失效；
- 成功访问、重复浏览、文件下载和错误密码尝试均不设置次数限制；
- 密码不得写死在前端代码中；
- 仍保留基础的服务端密码比较、会话签名、`HttpOnly`、`Secure` 和 `SameSite` 等安全属性。

实现方式：持久 Cookie 不使用固定到期天数，而使用长期 `Max-Age`；Cookie 载荷包含密码版本或配置更新时间指纹，修改密码时旧 Cookie 自动失效。

### 5.3 演示路径

展示路径改为当前 MVP 主线：

1. 首页；
2. 注册或登录；
3. `/console` 统一用户入口；
4. 名片资料、组件、产品与服务；
5. 发布公开主页；
6. 访客提交咨询形成 Lead；
7. 用户查看线索与分析；
8. `/jeepwork` 展示超级管理员治理。

旧 `/dashboard`、`/workbench` 和 `/enterprise-ai` 不再作为核心展示叙事；仅在真实兼容路由仍存在时作为内部过渡路径。

### 5.4 材料与证据

- 没有真实上传文件时，不显示“比赛资料已接通”或“已有离线备份”；
- 证据状态必须来自真实文件或数据库记录；
- GitHub CI 可以展示为“自动测试通过”，但不得等同于生产部署通过；
- 比赛中心继续负责 PPT、PDF、视频、截图和评委材料管理。

## 6. Jeepwork 定向收口

### 6.1 比赛入口

- 侧边栏只显示一个入口：`比赛中心`；
- 旧 `/jeepwork/showcase` 路由保留兼容；
- 旧路由自动跳转至 `/jeepwork/competition-center?tab=files`；
- 不保留两个并列入口造成认知冲突。

### 6.2 历史 admin 角色

- 数据库历史 `admin` 值保留；
- 后台不再允许新建或分配 `admin`；
- API 角色修改只接受 `super_admin` 或 `user`；
- 角色页继续显示历史 `admin` 账号，便于迁移；
- 历史 `admin` 只允许升级为 `super_admin` 或降级为 `user`；
- 删除“管理员拥有运营后台权限”的错误说明；
- 平台后台所有可见入口继续仅限 `super_admin`。

## 7. 数据源策略

本轮不做完整 Showcase 架构重写，但必须消除明显冲突：

- 公开页静态基础信息和真实状态统一放入单一配置模块；
- 后台数据库内容继续负责可编辑章节、文件、访问记录和开关；
- 公开页不得宣称所有内容均由后台即时修改，除非该部分确实来自数据库；
- 后续再单独规划将旧展示组件完全迁移到 Showcase V2 数据库内容源。

## 8. 错误处理

- Showcase 配置或数据库读取失败时，展示明确的中文降级状态，不伪造成功；
- 访问密码错误时允许立即重试；
- 修改密码后旧 Cookie 校验失败并回到密码页；
- 公司 Logo 加载失败时使用 Link168 文本品牌回退；
- 旧比赛后台路由跳转失败时保留可操作的返回链接。

## 9. 测试与验收

至少补充或更新以下测试：

1. Showcase 不再出现未备案、待补充、demo、每日重置等占位词；
2. 公司主体信息、备案号和公开邮箱准确；
3. Showcase 访问 Cookie 为长期持久 Cookie；
4. 修改密码版本后旧 Cookie 失效；
5. 密码错误尝试没有应用级次数限制；
6. Jeepwork 导航只包含一个比赛入口；
7. `/jeepwork/showcase` 跳转到新版比赛中心；
8. API 不再接受将用户设置为 `admin`；
9. 历史 admin 仍可被查询并迁移；
10. 可见 Jeepwork 路由继续全部为 `super_admin`；
11. TypeScript、ESLint、Jest、生产构建和 `git diff --check` 通过。
