# Link168 AI 客服 MVP 收口设计

**日期：** 2026-07-16  
**目标分支：** `codex/ai-reception-closeout-20260716`  
**起始基线：** `c0a93b2e2a2d21b34fad3bf151a089ce6dba91a4`

## 1. 目标

把现有 AI 接待从“界面和调用链存在，但配置来源重复、客户端保存缺口、快捷动作未闭环”的状态，收口为可测试、可配置、权限清晰的 MVP。

最终规则：

> 系统端控制供应商、安全、权限、额度和成本；客户端控制助手形象、业务资料、快捷按钮和自动回复。客户端无权修改或看到平台底层 AI 参数。

## 2. 本轮范围

### 2.1 系统端

仅 `super_admin` 可以配置并查看：

- AI 供应商；
- API Key、App ID、Workspace ID、Base URL；
- 模型、超时、温度、最大输出长度；
- AI 总开关、公众调用开关；
- 套餐权限、平台额度、用户额度和成本策略；
- 真实连接测试、供应商原始诊断和平台审计日志。

系统端配置继续使用现有 `AppConfig` 和 Jeepwork AI 配置中心，不向普通用户和公开访客返回供应商名称、模型名称、密钥、App ID、Base URL、Token 明细或供应商原始错误。

### 2.2 客户端

客户只能管理自己主页的经营配置：

- AI 接待开启或关闭；
- 助手名称；
- 欢迎语；
- 语气风格；
- 产品推荐开关；
- Lead 收集开关；
- 隐私提示；
- 快捷按钮和预设自动回复；
- 可引用的自有产品与知识资料。

客户端不提供供应商、模型、API Key、App ID、Base URL、Token 参数或底层错误详情。

### 2.3 访客端

访客只看到：

- 客户配置的助手名称；
- 欢迎语；
- “AI 生成内容，仅供参考”等合规提示；
- 客户配置并启用的快捷按钮；
- Link168 统一、去供应商品牌化的可用或失败文案。

访客不得看到阿里百炼、通义千问、OpenAI、DeepSeek 等供应商品牌和模型信息。

## 3. 明确排除

以下功能继续冻结，不属于当前 MVP：

- 企业客服坐席；
- 人工实时接管；
- 会话分配、轮询或抢单；
- 在线状态；
- WebSocket 实时客服；
- 客服主管后台；
- 坐席绩效和高级客服统计；
- 复杂举报处理中心。

## 4. 配置唯一来源

### 4.1 客户 AI 配置

`AiServiceConfig` 是客户 AI 接待经营配置的唯一来源。

当前名片 `ai-chat` 组件中的 `assistantName`、`greeting` 和 `tone` 属于重复配置。本轮收口后：

- `AiServiceConfig` 保存助手名称、欢迎语、语气、功能开关、隐私提示和快捷动作；
- `ai-chat` 名片组件只负责“是否放置、排序、隐藏和恢复”；
- 公开页渲染 AI 组件时，从服务端取得客户的 `AiServiceConfig` 展示配置；
- 后端构建 Prompt 时读取同一份 `AiServiceConfig`；
- 不允许出现页面显示一套、真实回答使用另一套的情况。

### 4.2 旧数据兼容

旧 `ai-chat` 组件 payload 继续允许读取，但只用于一次性兼容：

- 客户尚未建立 `AiServiceConfig` 时，可把旧 payload 的名称、欢迎语和语气作为创建默认值；
- 一旦 `AiServiceConfig` 存在，旧 payload 不再覆盖客户配置；
- 本轮不批量删除旧 payload，不破坏历史名片组件。

## 5. 快捷按钮与自动回复

### 5.1 数据结构

在 `AiServiceConfig` 增加 `quickActionsJson` 字段，以 JSON 数组保存最多 6 个快捷动作。

单个动作结构：

```ts
export type AiReceptionQuickAction = {
  id: string;
  label: string;
  type: "auto_reply" | "send_message" | "open_url" | "copy_text" | "call_phone";
  value: string;
  enabled: boolean;
  position: number;
};
```

字段规则：

- `id`：稳定 UUID；
- `label`：1–20 字；
- `type`：固定白名单；
- `value`：按类型校验，最多 1000 字；
- `enabled`：客户控制是否公开；
- `position`：客户控制顺序；
- 最多 6 个动作；
- 不允许脚本协议、内网地址或危险 URL。

### 5.2 行为

- `auto_reply`：点击后直接在对话窗口显示客户预设回复，不调用 AI、不扣额度；
- `send_message`：点击后将预设问题作为访客消息发送给 AI，执行正常权限和额度检查；
- `open_url`：打开客户配置并通过安全校验的公网链接；
- `copy_text`：复制客户配置内容；
- `call_phone`：调用经过格式校验的 `tel:` 电话动作。

平台不预设“联系人工”必须展示什么。客户自己决定按钮名称、类型、内容、数量和顺序。

## 6. API 设计

### 6.1 客户配置 API

新增或补齐：

`GET /api/dashboard/ai-service-config`

- 必须登录；
- 只返回当前用户自己的客户配置；
- 返回脱敏的客户经营配置，不含任何平台供应商字段；
- 没有记录时返回明确默认值，不伪造“已启用”。

`PUT /api/dashboard/ai-service-config`

- 必须登录；
- 只允许更新客户字段白名单；
- 服务端校验字符串长度、语气白名单、快捷动作数量、类型和 URL；
- 使用 `upsert` 保存当前用户记录；
- 不能更新 `AppConfig` 或供应商字段；
- 保存后重新验证公开主页缓存。

### 6.2 公开配置 API

新增：

`GET /api/public/[username]/ai-reception-config`

- 只在主页公开、用户已验证、AI 组件处于启用状态时返回；
- 只返回公开展示所需字段；
- 返回已启用并排序的快捷动作；
- 不返回供应商、模型、密钥、内部额度、平台配置或后台诊断。

公开页也可以由服务端页面直接注入配置，但必须保证响应数据遵循同一公开 DTO。

## 7. 权限与调用规则

执行优先级：

1. 系统安全规则；
2. 会员权限与额度；
3. 平台 AI 总开关和公众调用开关；
4. 客户 `AiServiceConfig.enabled`；
5. 当前名片 AI 组件是否启用；
6. 客户经营配置和快捷动作。

固定规则：

- 免费用户不能产生真实 AI 调用；
- 会员过期、冻结、额度不足时拒绝调用；
- `auto_reply`、`open_url`、`copy_text` 和 `call_phone` 不调用模型、不扣 AI 额度；
- `send_message` 执行完整 AI 权益、幂等和扣费链路；
- Provider 失败、输出审核失败或写库失败必须走现有退款补偿；
- 客户未配置的内容，AI 不得自行展示或编造。

## 8. 去供应商品牌化

### 客户端与访客端允许显示

- `Link168 AI 接待`；
- `AI 服务可用`；
- `AI 服务暂不可用，请稍后再试`；
- `本月剩余 AI 额度`；
- 客户自定义助手名称；
- 通用错误代码对应的中文用户文案。

### 客户端与访客端禁止显示

- 供应商名称；
- 模型名称；
- App ID、Workspace ID、API Key、Base URL；
- Token 用量；
- 供应商 request ID；
- 供应商原始异常文本；
- 供应商 HTTP 响应正文。

系统日志和 `super_admin` 真实连接测试页面可以保留这些内部信息，但密钥必须脱敏。

## 9. 错误处理

对客户和访客统一使用平台级错误文案：

- 未启用：`AI 接待暂未开启。`；
- 无权益：`当前主页暂未开通 AI 接待。`；
- 额度不足：`当前主页的 AI 服务额度已用完。`；
- 未配置：`AI 服务暂不可用，请稍后再试。`；
- Provider 失败：`AI 接待暂时不可用，本次未消耗额度。`；
- 输入不安全：保留现有明确合规提示；
- 网络失败：`网络连接失败，请稍后再试。`。

供应商原始错误只进入服务端安全日志和超级管理员诊断，不进入客户或访客响应。

## 10. 测试与验收

### 10.1 服务端测试

必须覆盖：

- 未登录不能读取或保存客户配置；
- 用户只能读写自己的配置；
- 客户接口不能写入供应商字段；
- 快捷动作数量、类型、长度、URL 和电话校验；
- `AiServiceConfig` 成为真实 Prompt 和公开展示的唯一来源；
- 免费用户真实 AI 调用被拒绝；
- `auto_reply` 不调用 Provider、不扣额度；
- `send_message` 正常走幂等和扣费；
- Provider 失败退款；
- 客户和公开响应不泄露供应商信息。

### 10.2 前端测试

必须覆盖：

- 客户配置可加载、保存并刷新后保留；
- 用户端没有供应商、模型和密钥字段；
- 快捷动作支持新增、编辑、删除、启用、禁用和排序；
- 公开页只显示已启用动作；
- `auto_reply` 点击后直接显示预设内容；
- `send_message` 点击后发送预设问题；
- 公开页错误文案不暴露供应商。

### 10.3 全量门禁

- Prisma validate；
- Prisma generate；
- migration 在 PostgreSQL 16 执行；
- TypeScript；
- ESLint；
- Jest 全量；
- production build；
- `git diff --check`。

## 11. 完成定义

同时满足以下条件才算本轮收口完成：

1. 超级管理员继续能够配置并测试平台 AI；
2. 客户能够保存并读取自己的 AI 接待配置；
3. `AiServiceConfig` 是客户配置唯一来源；
4. 客户能够配置最多 6 个快捷按钮及自动回复；
5. 公开访客能够使用快捷动作和 AI 对话；
6. 客户端和访客端不暴露底层供应商与模型；
7. 免费用户不产生真实 AI 调用；
8. 调用失败的额度补偿保持有效；
9. 企业坐席和实时人工客服没有被引入；
10. 全部自动化门禁通过。
