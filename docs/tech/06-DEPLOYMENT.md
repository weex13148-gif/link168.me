## 2. 部署技术栈（基于 package.json / 实际文件）

| 项目 | 说明 |
|------|------|
| 应用 | Next.js（App Router），通过 `next build` + `next start` 启动 |
| 数据库 | PostgreSQL，通过 Prisma 连接 |
| 静态资源 | `public/` 目录由 Next.js 直接服务 |
| 反代（建议） | Nginx：反代到 `127.0.0.1:3000`，统一处理 HTTPS、静态资源、压缩 |
| 进程管理（建议） | PM2 或 systemd，保证进程常驻并可重启 |
| HTTPS 证书 | 建议使用 Let's Encrypt 或云厂商证书服务，由运维管理 |
| Cookie Secure | HTTPS 环境下开启 `COOKIE_SECURE=true`；未启用 HTTPS 时必须为 `false` |

## 3. 环境变量（仅列名称，不写值）

- `DATABASE_URL`：PostgreSQL 连接串
- `ADMIN_SECRET`：管理员后台 / 管理员 API 的保护密钥（至少 32 字符，随机生成）
- `SESSION_SECRET`：Session 签名用（如需；若代码中仅随机生成 Token，也可作为额外加盐字段）
- `COOKIE_SECURE`：`true` / `false`，决定 Cookie 是否标记 Secure
- 邮件相关（如配置 SMTP）：`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASS`、`SMTP_FROM`
- 其他 `NEXT_PUBLIC_*` 公开变量：仅写确实需要前端读取的变量

所有变量的 **默认示例结构** 位于仓库根目录 `.env.example`，可复制为 `.env.local` 或 `.env.production` 后填入实际值。

## 4. 部署步骤（原则性描述，不含真实命令细节）

1. **确认版本**：确认当前要部署的 Git commit / 分支，与老板确认后再操作
2. **拉取代码**：在服务器上拉取目标版本
3. **安装依赖**：`npm install`（生产环境建议 `npm ci`）
4. **数据库迁移**：`npx prisma migrate deploy`（需由持有数据库密码的人执行）
5. **构建**：`npm run build`
6. **启动 / 重启**：通过 PM2 或 systemd 启动或重启 Next.js 服务
7. **反代与 HTTPS**：Nginx 配置指向本地 3000 端口，确保 HTTPS 生效
8. **Smoke Test（上线后 30 分钟内必须完成）**：依次检查
   - 访问 `https://link168.me` 首页 → 正常加载
   - 注册新账号 → 邮箱密码注册成功，bcrypt 存储
   - 登录 → Session + HttpOnly Cookie 生效
   - Dashboard → 编辑用户名/显示名/简介/头像 → 保存成功
   - 添加链接 → 新增/编辑/删除链接 → 保存成功
   - 访问公开主页 `/用户名` → 头像、简介、链接、品牌 Footer 正常显示
   - 提交举报 → 内容入库
   - 管理员查看举报列表/详情 → 正常
   - 生成公开主页二维码 → 扫码后可访问
   - `COOKIE_SECURE` 在 HTTPS 环境下为 `true`
9. **记录**：在运维/部署日志中记录"谁、何时、部署了哪个版本"
10. **回滚方案**：如出现故障，回滚到上一个可用 commit，重新 `build` → 重启

## 5. 关键注意事项（必须遵守）

| 项目 | 规则 |
|------|------|
| 自动部署 | **严禁**配置任何自动部署（GitHub Actions / CI 自动推送生产） |
| 密钥管理 | 密码、`ADMIN_SECRET`、`SESSION_SECRET`、SMTP 密码**不得提交到 Git** |
| 提交前检查 | `.env`、`.env.local`、`.env.production` 必须在 `.gitignore` 中（已满足） |
| HTTPS / Cookie | 线上使用 HTTPS 时，`COOKIE_SECURE=true`；未启用 HTTPS 时必须 `false` |
| 数据库 | 数据库用户名、连接串由运维管理；开发者仅在本地使用独立数据库 |
| PM2 故障预防 | 定期检查进程状态；避免配置错误的 watch 模式；启动脚本使用 `--env production` 或同等机制 |
| 部署权限 | 仅由老板或老板授权的运维执行线上部署；开发者不承担生产部署权限 |
| 日志 | 访问日志、错误日志、PM2 日志路径由运维记录到独立文档 |
| 备份 | PostgreSQL 数据库需定期备份，由运维制定备份/恢复策略 |
