# link168.me 安全与密钥管理说明（骨架 · 仅记录原则）

版本：v0.1 MVP Draft
更新日期：2026-06-18

> ⚠️ **严禁**：本文件 **不包含** 任何真实密码、真实密钥、真实连接串、真实 `ADMIN_SECRET` / `SESSION_SECRET` / 数据库密码 / SMTP 密码。所有真实值仅由老板 / 运维在生产环境本地管理。

---

## 1. 密钥清单（仅列名称与用途）

| 环境变量名 | 用途 | 最小长度建议 | 存放位置 |
|-----------|------|-------------|---------|
| `DATABASE_URL` | PostgreSQL 连接串（host/port/user/password/dbname） | 不适用 | 服务器本地 `.env.production` 或进程环境 |
| `ADMIN_SECRET` | 管理员 API / 管理员页面的访问保护 | ≥ 32 字符，随机 | 同上 |
| `SESSION_SECRET` | Session Token 加盐或签名（如使用） | ≥ 32 字符，随机 | 同上 |
| `COOKIE_SECURE` | 是否把 Cookie 标记为 Secure（HTTPS 环境必须为 `true`） | `true`/`false` | 同上 |
| SMTP 相关变量（如有） | 邮件发送账号与密码 | SMTP 服务规定 | 同上 |
| 其他第三方 API Key（如有） | 如未来接入支付 / 短信 / AI 等 | 按服务商要求 | 同上 |

## 2. 密钥生成与轮换原则

- **生成方式**：使用系统级随机源生成，例如 `openssl rand -hex 32` 或其他安全随机工具
- **禁止事项**：不得使用"123456""admin""link168"等可猜值；不得复用开发 / 测试环境的密钥
- **轮换周期**：建议 90 天内轮换一次 `ADMIN_SECRET` / `SESSION_SECRET`；人员变更（离职）时强制轮换
- **轮换影响**：
  - 轮换 `ADMIN_SECRET`：需要管理员使用新密钥
  - 轮换 `SESSION_SECRET`：如该值仅为加盐并不影响 Session 表，则视代码实现决定是否让用户掉线

## 3. 密钥存储与访问权限

- **仓库永不提交**：`.env`、`.env.local`、`.env.production` 必须在 `.gitignore` 中（已满足）
- **生产环境只存服务器本地**：不写入 Git、不写进 Docker 镜像、不贴在共享文档
- **最小权限访问**：仅老板 / 运维持有生产密钥，开发者在本地使用独立的开发数据库与本地密钥
- **本地自测**：开发成员在本地从 `.env.example` 复制为 `.env.local` 后，填入各自本地值

## 4. 密码安全（用户侧）

- **存储**：用户密码使用 bcrypt 哈希存储，数据库 **不存明文**
- **传输**：生产环境必须使用 HTTPS，`COOKIE_SECURE=true`
- **Cookie**：登录态使用 **HttpOnly + SameSite** Cookie，浏览器脚本不可读取
- **登录失败**：写入 `LoginAttempt` 表，用于识别撞库 / 暴力破解模式，并在阈值后锁定账户或增加限速

## 5. 权限分级与管理员安全

- **角色**：`user` / `admin` / `super_admin`
- **系统账号**：`isSystem=true` 的账号不可被普通管理员修改或重置密码
- **管理员 API**：需通过 `ADMIN_SECRET` 或等效的权限校验才能访问（见 `src/lib/admin-auth.ts`）
- **管理员重置用户密码**：有限制，不能操作系统账号，操作留痕

## 6. IP 记录与隐私与审计（规划）

- **已在 Schema 预留**：`Session` 表中记录 `ipAddress`、`userAgent`
- **留存策略（规划）**：详细 IP 建议留存 90 天；审计日志不少于 6 个月；超过留存期后脱敏或删除
- **普通用户不可查看完整 IP**（规划）：仅 super_admin 在风控场景下可查看，并留下"谁 / 何时 / 查看对象 / 原因"的记录
- 详见 `docs/SUPER_ADMIN_PRD.md` / `docs/AUDIT_LOG_SCHEMA_PLAN.md`

## 7. 输入校验与防护

- **SQL 注入**：所有数据访问通过 Prisma 参数化查询完成，禁止手写 SQL 字符串拼接
- **XSS**：用户输入的 displayName / bio / 链接标题等在 React 渲染时默认转义
- **CSRF**：依赖 HttpOnly + SameSite Cookie + 同源主要访问模式；如未来增加跨域表单，需补充 CSRF Token
- **URL 跳转**：所有链接跳转建议提醒用户"将离开本网站"（如后续实现跳转代理），避免钓鱼滥用

## 8. 安全自检清单（每次部署前至少核对一次）

- [ ] `.env` 相关文件是否仍在 `.gitignore` 中
- [ ] 代码、日志、文档中是否出现了真实密钥 / 真实连接串
- [ ] `COOKIE_SECURE` 在 HTTPS 环境下是否为 `true`
- [ ] `ADMIN_SECRET` 是否已替换为强随机值并仅管理员可知
- [ ] 用户密码是否都以 bcrypt 哈希存储
- [ ] 管理员 API 是否都经过了权限校验
- [ ] 数据库备份文件是否加密 / 不外传

## 9. 安全事件响应流程（简要）

1. **发现可疑**：发现异常登录、异常举报、密钥可能泄露等
2. **立即隔离**：停掉可疑 Session；如密钥可能泄露，立即更换相关密钥并重启服务
3. **留证**：保留日志 / 数据库快照（在不违反隐私的前提下）
4. **上报**：通知老板和参与的运维人员
5. **复盘**：事后补齐 `docs/archive/` 下的安全事件记录（不含敏感值）
