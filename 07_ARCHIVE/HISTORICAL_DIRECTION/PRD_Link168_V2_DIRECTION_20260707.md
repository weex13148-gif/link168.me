## 1. 产品定位

Link168 V2 是一个经营名片 SaaS，帮助个人创业者、小商家、自由职业者和轻量销售团队快速创建可传播的公开名片，并把访客访问转化为可跟进客户线索。

一句话：用一张经营名片完成展示、获客、留资、分析和付费升级。

## 2. 用户与场景

### 核心用户

- 个人创业者：需要一个比朋友圈简介更正式的对外入口。
- 小商家：需要展示服务、产品、联系方式、二维码和案例。
- 自由职业者：需要把作品、服务和咨询入口组合起来。
- 销售/顾问：需要可传播的个人名片并跟踪客户访问。
- 平台运营：需要管理用户、订单、内容风险、AI 使用和系统状态。

### 核心场景

- 用户注册后 5 分钟内发布第一张公开名片。
- 用户把名片链接或二维码发给客户。
- 客户访问名片、查看服务、复制联系方式、提交咨询或进入 AI 接待。
- 用户在控制台查看访问、线索、热门产品和跟进状态。
- 用户因为更多模板、更多产品、AI 接待和数据分析升级会员。

## 3. 产品目标

### MVP 目标

- 完成从注册、创建名片、发布名片、访客访问、线索沉淀、用户跟进到会员升级的闭环。
- 统一用户侧入口为 `/console`，避免 `/dashboard` 与 `/workbench` 双路径继续扩散。
- 平台管理统一为 `/jeepwork`，不保留旧 `/admin` 作为主线后台。

### 商业目标

- 让免费用户能真实发布名片，但在模板、产品数量、AI 接待、数据分析、品牌露出等维度形成升级动机。
- 让 Plus/Pro 会员权益在服务端真实生效。
- 让订单、退款、到期、降级和 AI 成本能被平台追踪。

## 4. 非目标

- V2 MVP 不做独立展示中心 `/showcase`。
- V2 MVP 不做独立企业 AI 产品线。
- V2 MVP 不做完整 CRM、营销自动化或私域群发。
- V2 MVP 不做复杂组织销售流程。
- V2 MVP 不继续维护旧 `/admin` 页面。

## 6. 功能需求

### 6.1 首页与注册登录

用户必须能从首页理解 Link168 的价值，并进入注册/登录。

验收标准：

- 首页第一屏明确表达“经营名片 + 线索转化”。
- CTA 指向注册、登录或模板预览。
- 注册后必须进入控制台创建流程。
- 登录、注册、忘记密码、邮箱验证、退出登录可用。

### 6.2 模板中心

模板中心承接参考图中的产品审美和决策入口，但不要让模板中心变成独立展示站。

验收标准：

- 可浏览模板列表。
- 可进入模板详情。
- 可预览移动端名片效果。
- 已登录用户可用模板创建或替换名片主题。
- 未登录用户点击使用模板进入注册。

### 6.3 控制台首页

控制台首页是用户日常经营入口，不再让用户在 `/dashboard` 与 `/workbench` 之间切换。

验收标准：

- 显示名片发布状态。
- 显示公开链接和二维码入口。
- 显示今日/本周访问、线索、转化摘要。
- 显示未完成配置项。
- 显示会员状态和升级入口。

### 6.4 名片编辑器

名片编辑器负责创建和维护公开经营名片。

核心字段：

- 用户头像、名称、职业/身份、简介。
- 联系方式：手机号、微信、邮箱、地址、外部链接。
- 模块：链接、产品/服务、图片、视频、二维码、公告、FAQ。
- 主题：颜色、字体、布局、背景、按钮样式。

验收标准：

- 支持保存草稿和发布。
- 支持移动端实时预览。
- 服务端校验用户名唯一性、资料合法性、上传限制。
- 免费版和会员版权益在服务端限制。

### 6.5 公开名片

公开名片是核心转化页面。

验收标准：

- 访问 `/[username]` 可看到用户资料、产品、联系方式和行动按钮。
- 访客行为被记录：访问、点击、产品查看、联系方式点击、留资。
- 支持访客提交咨询线索。
- 支持举报入口和内容安全拦截。
- 页面移动端优先，桌面端不应破坏名片体验。

### 6.6 产品/服务管理

用户可以维护自己要售卖或展示的产品服务。

验收标准：

- 支持创建、编辑、下架产品/服务。
- 字段包含标题、简介、价格或价格说明、图片、详情、联系方式。
- 产品可显示在公开名片。
- 产品访问和咨询可进入线索来源。
- 免费版数量有限，Plus/Pro 可扩展。

### 6.7 线索管理

线索是商业闭环的关键，不只是表单记录。

验收标准：

- 线索字段包含姓名/称呼、联系方式、来源、感兴趣产品、备注、状态、创建时间。
- 状态至少包含：新线索、已联系、跟进中、已成交、无效。
- 支持按来源、状态、时间筛选。
- 支持跟进备注。
- 线索必须能从公开名片、产品咨询、AI 接待进入。

### 6.8 数据分析

分析能力服务于升级和经营复盘。

验收标准：

- 统计访问趋势、访客来源、按钮点击、产品热度、线索转化。
- 免费版显示基础统计。
- Pro 显示更长周期、更完整来源和转化漏斗。
- 数据展示不能只做前端假数据。

### 6.9 AI 接待

AI 接待必须围绕名片和产品转化，不做泛聊天。

验收标准：

- AI 根据名片资料、产品信息和知识库回答。
- AI 能引导访客留下联系方式。
- AI 使用量计入用户额度。
- 免费用户不能无限消耗真实 AI 成本。
- Jeepwork 可查看 AI 使用、风险和成本。

### 6.10 会员与支付

会员系统必须闭环，不只展示套餐。

验收标准：

- 套餐权益统一配置。
- 订单创建、支付回调、订单状态更新可用。
- 支付宝退款调用真实退款接口。
- 到期后自动降级或限制权益。
- 服务端根据会员状态限制产品数量、AI 使用、上传容量和数据范围。

### 6.11 账号与安全

验收标准：

- 支持修改密码、退出登录、查看会话。
- 支持账号注销流程。
- 重要操作有服务端鉴权。
- 敏感配置不进入仓库。

### 6.12 Jeepwork 平台治理

Jeepwork 是唯一平台后台。

验收标准：

- 可查看用户、会员、订单、退款、举报、AI 使用、系统健康。
- 可冻结违规账号或限制内容。
- 管理操作写入审计日志。
- 管理 API 必须鉴权。

## 7. 权益建议

| 能力 | 免费版 | Plus | Pro | 企业版 |
| --- | --- | --- | --- | --- |
| 公开名片 | 1 张 | 1 张 | 多张或高级配置 | 多成员名片矩阵 |
| 模板 | 基础模板 | 更多模板 | 全部模板 | 企业模板 |
| 产品/服务 | 少量 | 扩展 | 大量 | 团队共享 |
| 线索管理 | 基础列表 | 筛选和备注 | 完整跟进 | 统一线索池 |
| 数据分析 | 7 天基础 | 30 天 | 180 天和漏斗 | 团队报表 |
| AI 接待 | 体验或关闭 | 小额度 | 高额度 | 专属额度 |
| 品牌露出 | 有 | 可弱化 | 可隐藏 | 可定制 |

具体价格可在运营验证后调整，但权益边界必须先落到代码。

## 8. 数据模型要求

优先复用当前 Prisma 能力，核心模型包括：

- User：账号和身份。
- Profile：公开名片主体。
- Link/ProfileModule：名片模块。
- Product：产品/服务。
- Lead：客户线索。
- Visit/AnalyticsEvent：访问和行为。
- Order/Membership：订单和会员。
- Workspace/WorkspaceMember：团队能力的后续基础。
- AiUsage/AiCredit：AI 使用和额度。
- Notification：通知。
- AdminAuditLog：平台审计。

若现有模型字段不足，应在不破坏主闭环的前提下补齐。

## 9. 路由迁移原则

- `/console` 是用户侧唯一未来入口。
- 当前 `/dashboard` 和 `/workbench` 的可用能力可以先被复制保留，但后续必须合并。
- `/jeepwork` 是平台侧唯一后台。
- 旧 `/admin` 不进入 V2 主分支。
- `/showcase` 暂不进入 V2 主分支。
- `enterprise-ai` 暂不进入 V2 主分支。

## 10. 验收指标

### 产品验收

- 新用户能在 5 分钟内创建并发布一张名片。
- 公开名片能产生访问记录。
- 访客能提交线索。
- 用户能在控制台看到线索和基础统计。
- 用户能看到会员权益和升级入口。
- Jeepwork 能查看用户、订单、内容和系统健康。

### 工程验收

- `npm run lint` 通过。
- `npm run typecheck` 通过。
- 无 `.env`、`.env.local`、`node_modules`、`.next`、上传文件进入分支。
- 关键 API 有服务端鉴权和权益校验。
- 文档、代码、路由命名保持一致。

## 11. 风险与待确认

- 套餐价格需要最终运营确认。
- 模板中心是否需要独立上线时间点需确认。
- AI 接待成本模型需要结合真实供应商价格复核。
- 企业版不要抢占 MVP 开发资源，只保留数据结构和后续接口余地。
