## 1. 文档目标与事实标记

本 PRD 将产品宪法落实为当前可开发、可验收、可运营的产品要求，并解决过去“代码存在就被写成完成”“多个 Agent 各自理解需求”“外部 API 未配置却声称通过”等问题。

所有功能必须使用以下状态：

- **【已存在】**：仓库中存在可定位的代码或数据结构；
- **【部分闭环】**：有基础代码，但用户流程、权限、状态、持久化或公开展示不完整；
- **【待开发】**：当前没有满足需求的实现；
- **【待修复】**：已有实现存在明确 Bug 或安全阻断；
- **【待配置测试】**：代码结构可检查，但必须由老板配置真实第三方 API 后才能验证；
- **【待服务器测试】**：必须在真实域名、Nginx、PM2、HTTPS 或公网回调环境验证；
- **【已验收】**：通过独立复审和规定测试，且没有已知阻断项。

不得把【已存在】或【部分闭环】写成【已验收】。

## 2. 产品定位与当前目标

> **Link168 是面向个人创业者、自媒体、小商家、一人公司和轻量经营团队的 AI 经营名片与商业基础设施平台。**

当前版本的唯一目标是打通真实经营闭环：

```text
注册与登录
→ 创建并装修经营名片
→ 添加产品、服务、图片、联系方式和平台链接
→ 发布并分享
→ 访客访问和咨询
→ AI 第一轮接待或转人工
→ 留下真实需求
→ 形成客户线索
→ 商家查看和跟进
→ 记录成交或关闭
→ 查看访问、咨询、留资和转化数据
```

本版本不以增加大量新页面或复杂企业功能为目标。

## 4. 用户、角色与权限

### 4.1 访客

访客可以：

- 访问已发布且允许公开的经营名片；
- 查看公开产品、服务、图片和联系方式；
- 点击平台链接；
- 提交咨询和联系方式；
- 使用名片主人已开通的访客 AI 接待；
- 要求本人联系。

访客不得进入用户控制台、企业后台或 Jeepwork。

### 4.2 免费用户

免费用户可以完成基础经营名片闭环，包括：

- 创建和发布个人经营名片；
- 使用基础组件；
- 添加产品与服务；
- 添加图片、联系方式、二维码和常用平台链接；
- 查看基础访问和线索；
- 人工跟进客户。

免费版不自带真实 AI 调用权益。所有真实 AI 调用必须由服务端权益判断，不得仅依赖前端隐藏。

### 4.3 Plus / Pro

Plus 和 Pro 属于个人付费会员，可按照正式套餐配置获得：

- AI 工作台；
- 访客 AI 接待；
- 知识库；
- 高级模板和装修；
- 更长分析周期；
- 对应的品牌、域名、存储和额度权益。

具体价格和额度由服务端套餐配置维护，页面不得写死与服务端冲突的数字。

### 4.4 企业成员与企业管理员

企业成员只能使用本企业授权的数据和企业共享能力。企业管理员只能管理本企业成员、名片、产品、知识库、线索、额度、域名和报表。

企业管理员不得访问其他企业、全站用户、平台密钥或平台最高权限。

### 4.5 平台最高权限

平台级最高权限只保留：

```text
super_admin
```

不得重新引入边界模糊的系统管理员角色。平台级配置和高风险操作统一进入 `/jeepwork`，并记录审计日志。

真实邮件发送属于【待配置测试】。未配置阿里云邮件推送时必须安全失败，不得显示“验证码已发送”。

# 7. 用户经营名片与组件闭环

## 7.1 完成定义

组件只有同时满足以下条件才算完成：

1. 用户可以从后台找到中文添加入口；
2. 可以新增；
3. 可以编辑；
4. 可以保存并显示保存状态；
5. 可以排序；
6. 可以隐藏和恢复；
7. 可以删除；
8. 刷新页面后仍然存在；
9. 手机预览正确；
10. 公开页正确；
11. 权限和错误状态正确；
12. 相关点击或提交能够产生真实事件或 Lead。

只存在字段、API、渲染组件或演示 UI 不等于完成。

## 7.2 本轮组件范围

本轮必须收口：

- 普通链接；
- 文本和分组标题；
- 产品卡片 `product-card`；
- 服务卡片 `service-card`；
- 优惠活动 `offer`；
- 预约 `booking`；
- 报价咨询 `quote`；
- 联系表单 `contact-form`；
- 电话、邮箱、微信号和地址；
- 图片、视频、FAQ 和 AI 接待入口的已有能力兼容。

组件数据必须采用服务端权限校验，用户不能修改其他用户或其他 Workspace 的组件。

## 7.3 编辑器状态

至少显示：

```text
未保存
保存中
已保存
保存失败
已发布
已下线
```

不得点击后没有反馈，也不得前端显示成功但服务端没有持久化。

## 7.4 手机端

在 360–430px 宽度下：

- 不横向溢出；
- 添加和编辑按钮可点击；
- 弹窗不超出屏幕；
- 排序有可用的触摸方案；
- 图片和平台 Logo 选择器可正常使用；
- 预览与公开页一致。

# 9. 常用平台预设 Logo 与链接识别

## 9.1 当前事实

当前项目已经存在按 URL 识别部分平台并显示 Emoji 的基础，但不等于真实平台 Logo 闭环。

已知现状：

- 平台自动识别结果主要是 Emoji；
- 没有完整的平台 Logo 搜索选择器；
- 用户不能稳定手动选择抖音、小红书等真实平台 Logo；
- API 主要接受 `default`、`emoji` 和 `custom`；
- 公开页和后台能够显示已有 `iconUrl` 或 `iconValue`，但没有统一平台 key 语义；
- 需要继续兼容旧 Emoji 和自定义图标数据。

## 9.2 用户场景

用户添加抖音链接时：

```text
输入 douyin.com 或 v.douyin.com 链接
→ 自动识别为抖音
→ 显示抖音平台 Logo
→ 用户可以手动更换或保持自动
→ 保存
→ 刷新后仍然存在
→ 手机预览和公开页显示相同 Logo
```

## 9.3 首批平台

至少支持：

- 微信、企业微信、QQ、微信号；
- 抖音、小红书、快手、微博、哔哩哔哩、知乎；
- 淘宝、天猫、京东、拼多多、闲鱼；
- 美团、大众点评；
- 支付宝；
- 高德地图、百度地图；
- 钉钉、飞书；
- GitHub、Gitee；
- 电话、邮箱、地址和通用网站链接。

## 9.4 配置结构

平台定义至少包含：

```ts
type PlatformDefinition = {
  key: string;
  name: string;
  aliases: string[];
  domains: string[];
  iconPath: string;
  enabled: boolean;
  sortOrder: number;
};
```

优先使用统一代码配置和本地静态资源，不要求本轮建立复杂 Logo 管理后台。

保存方案优先采用：

```text
iconType = platform
iconValue = douyin
```

如果当前数据模型可以安全复用现有字段，不强制新增 Prisma 字段。需要数据库变更时，只能由共享数据合同 Agent 统一决定并提供 migration。

## 9.5 选择优先级

图标显示规则：

```text
用户明确手动选择
→ 用户自定义上传
→ 自动域名识别
→ 网站 favicon
→ 通用链接图标
```

只有用户选择“自动识别”模式时，修改 URL 才能自动切换平台；不得覆盖用户已明确选择的图标。

## 9.6 合规

- 禁止第三方图片热链；
- 记录资源来源和更新时间；
- 不得显示“官方合作”“官方认证”等误导性文案；
- Logo 不得替代 URL 安全校验；
- 自定义图标仍需文件和内容安全检查。

# 11. AI Provider、知识库与安全降级

## 11.1 架构

AI 拆为两层：

```text
业务层：用户、Workspace、公开资料、知识库、权限、线索、转人工和审计
模型层：阿里百炼 Provider、未来备用 Provider
```

业务层不得依赖某一个模型的专有字段贯穿全系统。

## 11.2 配置

模型 App ID、API Key、接口地址、DashScope Workspace ID、超时、启停和额度配置由服务端受控读取，不得写死在客户端。

Link168 Workspace ID 与 DashScope Workspace ID 必须明确区分。

## 11.3 故障降级

模型未配置、超时、限流或不可用时：

- 公开名片继续展示；
- 产品和服务继续展示；
- 联系方式和联系表单继续可用；
- 可以提示 AI 暂时不可用；
- 不得返回伪造回答；
- 不得导致整个公开页 500。

## 11.4 知识资料分级

- **公开资料：** 可以用于访客回答；
- **内部资料：** 仅授权商家和员工查看；
- **禁止资料：** API Key、密码、支付配置、数据库连接、私钥和内部安全信息。

AI 不得自动读取未授权的后台资料。

## 11.5 真实测试

百炼真实回答属于【待配置测试】。在老板配置后台 API 前，本轮只允许测试 Provider 接口、权限、参数、错误转换、Mock 和安全降级。

# 12. 转人工与客户线索

## 12.1 转人工触发条件

出现以下场景时 AI 必须转人工：

- 无法从公开知识确认答案；
- 客户要求正式报价；
- 定制服务；
- 合同、退款、售后和投诉；
- 高风险行业问题；
- 客户明确要求本人联系。

## 12.2 高价值线索

转人工后至少记录：

- 客户关注内容；
- 主要问题；
- 联系方式；
- 是否明确要求本人联系；
- 来源页面和组件；
- 来源产品或服务快照；
- AI 对话摘要；
- 推荐跟进动作。

## 12.3 Lead 状态

统一为：

```text
新线索 → 已查看 → 跟进中 → 已成交 / 已关闭
```

旧的“已联系”状态如已存在，应在兼容和迁移方案中处理，不得同时维护两套互相冲突的产品状态。

## 12.4 跟进记录

每次跟进独立记录时间、操作者、内容和状态变化，不把全部历史无限追加到一个备注字段。

# 13. 数据分析

核心只收口四类指标：

1. **访问：** 公开页真实访问；
2. **咨询：** AI 提问、联系按钮或咨询入口行为；
3. **留资：** 产生有效联系方式和需求；
4. **转化：** Lead 被标记为已成交。

可以在此基础上展示来源、组件、产品和时间趋势，但不得为了图表数量重复埋点或制造无商业意义指标。

要求：

- 真实事件入库；
- 幂等或去重规则明确；
- 用户只能查看自己的聚合数据；
- 企业只能查看本 Workspace；
- 原始 IP 只在必要的安全权限下使用；
- 不允许随机数或演示数据冒充真实统计。

# 14. 社媒 Agent

社媒 Agent 可以：

- 根据商家资料生成文案；
- 生成小红书、抖音、公众号等平台适配版本；
- 给出发布时间、标题和素材建议；
- 生成待发布草稿。

社媒 Agent 不得：

- 未经用户确认自动登录平台；
- 未经逐次确认自动发布；
- 自动群发或骚扰；
- 使用用户未授权的素材；
- 把生成草稿写成已经发布。

真实跨平台发布 API 不属于本轮范围。未来增加时必须保留确认人、时间、平台、内容版本和发布结果。

# 15. 会员、支付、邮件和第三方接口

## 15.1 支付

当前正式收款方向为支付宝。必须遵守：

- 服务端创建订单；
- 金额使用订单快照；
- 异步通知验签；
- 校验 AppId、商户、金额、交易状态和订单状态；
- 回调幂等；
- 主动查询作为补偿；
- 退款同步权益、额度和相关业务记录；
- 不得仅凭前端跳转写支付成功。

真实下单、支付回调和退款属于【待配置测试】及【待服务器测试】。

## 15.2 邮件

阿里云邮件推送用于验证码、审核和必要通知。必须具备频率限制、有效期、重发限制、错误处理和日志脱敏。

真实邮件发送属于【待配置测试】。

## 15.3 外部 API 统一原则

所有外部业务 API 必须：

- 以官方文档为准；
- 由服务端调用；
- 受控读取配置；
- 未配置时安全失败；
- 日志不输出密钥；
- 错误码转换为清楚的用户提示；
- 不能把 Mock 写成真实通过。

11. 普通企业成员只能读取自己的公开名片记录，owner/admin 才能管理全部；
12. 补齐安全攻击用例和路由测试。

当前企业官网使用 owner 资料和产品作为回退时，必须明确标记为 MVP fallback，不能冒充完整 Workspace 级企业数据。

# 17. 企业 AI 额度 D4 当前修复要求

D4 当前状态为【待修复】，不得直接合并或部署。

必须完成：

1. 请求缺少 `workspaceId` 时，在任何数据库查询前返回明确错误；
2. 企业成员使用企业 AI 时不要求个人套餐有 AI 权益；
3. 企业路由只扣企业共享额度，不再同时扣个人 Credits；
4. 使用稳定 `idempotencyKey` 防止网络重试重复预留；
5. 额度状态至少支持：

```text
pending
reserved
succeeded
refund_pending
refunded
failed
```

6. reserve、confirm 和 refund 使用原子条件状态转换；
7. confirm 和 refund 并发时不能互相无条件覆盖；
8. 所有失败出口都检查真实退款结果；
9. 只有真实退款成功才显示“额度已退回”；
10. 退款失败或处理中必须显示“退款处理中/需要对账”；
11. confirm 失败不得返回普通 AI 成功；
12. 删除重复和不可达代码；
13. 更新旧 boolean 测试以适配结构化结果；
14. `package.json` 和 `package-lock.json` 保持一致；
15. 使用真实隔离 PostgreSQL 执行并发测试；没有测试数据库时明确写“真实数据库并发尚未验证”，不得建议合并。

# 18. 方案 C：两批五 Agent 开发与总控收口

老板已选择方案 C：

```text
第一轮 5 个 Agent
→ 第一轮总控集成和门禁
→ 第二轮 5 个 Agent
→ 最终总控集成和修复
→ GitHub 独立复审
→ 决定是否合并
```

不得 10 个 Agent 同时自由修改相邻文件。

## 18.1 第一轮：基础与高风险

### Agent 1：共享数据合同

唯一允许决定和修改：

- Prisma Schema 和本轮 migration；
- 共享 TypeScript 类型；
- 组件类型、媒体类型、图标类型；
- Lead 状态；
- AI Provider 标准接口；
- 四类统计事件定义。

原则：能复用现有字段就不改数据库。

### Agent 2：D2 企业域名安全

只执行第 16 章，不扩展企业官网。

### Agent 3：D4 企业额度安全

只执行第 17 章，不调用真实百炼。

### Agent 4：图片与媒体底层

负责上传、替换、删除、校验、权限、失败状态、旧文件规则和通用媒体组件，不负责整个控制台页面拼装。

### Agent 5：常用平台 Logo

负责平台配置、本地资源、自动识别、手动搜索选择、旧数据兼容和统一渲染。

## 18.2 第一轮门禁

第一轮总控 Agent 只允许集成和修复，不允许新增范围。

必须执行：

```bash
rm -rf node_modules .next
npm ci
npx prisma format
npx prisma validate
npx prisma generate
npm run typecheck
npm run lint
npm test
npm run build
git diff --check
git status --short
```

必须专项检查：

- D2 Host 绕过关闭；
- D4 退款文案和并发状态正确；
- 图片接口未配置时安全失败；
- 抖音链接显示抖音 Logo；
- 旧 Emoji 链接正常；
- 没有重复代码；
- 没有越权修改 Prisma。

第一轮失败时不得启动第二轮。

## 18.3 第二轮：用户业务闭环

### Agent 6：组件后端

负责组件新增、编辑、保存、排序、隐藏、恢复、删除、权限和持久化。

### Agent 7：组件编辑器和手机预览

负责中文组件入口、编辑表单、媒体入口、平台 Logo 选择器接入、保存状态、手机操作、统一预览和公开渲染。

### Agent 8：AI Provider 与安全降级

负责 Provider 接口、百炼适配、备用插槽、配置读取、超时和错误转换。只做无真实密钥测试。

### Agent 9：转人工与 Lead

负责转人工条件、高价值线索、摘要、产品快照、Lead 状态和跟进记录。

### Agent 10：经营指标和社媒确认

负责访问、咨询、留资、转化四类指标，以及社媒发布必须人工确认的产品边界。

## 18.4 文件所有权

每个 Agent 必须使用独立 worktree 和分支。不得同时修改同一文件。

需要修改其他 Agent 所有文件时：

1. 输出接口需求；
2. 由文件所有者修改；
3. 或留给总控 Agent 在集成阶段接线。

不得通过复制粘贴绕过所有权，避免再次出现重复代码和接口不一致。

## 18.5 最终总控 Agent

总控 Agent 只负责：

- 按固定顺序集成；
- 解决接口接线；
- 修复编译、测试和集成回归；
- 删除重复逻辑；
- 统一命名和渲染。

总控 Agent 不得：

- 改产品方向；
- 新增组件或功能；
- 重写 PRD；
- 直接合并 master；
- 部署服务器；
- 自己宣布已验收。

最终只推送集成审查分支，再进行独立 GitHub 代码复审。

# 20. 核心验收用例

## 20.1 用户装修

- 新用户能够添加产品、服务、优惠、预约、报价和联系表单；
- 修改后刷新数据不丢失；
- 排序、隐藏、恢复和删除真实生效；
- 手机预览与公开页一致；
- 390px 宽度无横向溢出。

## 20.2 图片

- 上传合法头像成功或在未配置时明确失败；
- 非法格式和超限文件被拒绝；
- 替换后显示新图片；
- 删除后公开页不再引用；
- 用户不能删除他人的媒体；
- 企业 Logo 与个人头像不混用。

## 20.3 平台 Logo

- 添加 `v.douyin.com` 链接自动识别抖音；
- 可以手动搜索并选择抖音；
- 保存和刷新后仍为抖音；
- 手机预览和公开页显示相同本地 Logo；
- 手动选择不会被 URL 自动覆盖；
- 旧 Emoji 和自定义图标正常显示；
- 未识别 URL 使用通用图标。

## 20.4 AI 和转人工

- Provider 未配置时名片和联系表单继续可用；
- AI 不编造正式报价；
- 客户要求本人联系时生成高价值 Lead；
- 合同、退款和售后问题转人工；
- 内部资料不会进入访客回答。

## 20.5 D2

- 直接访问主域名 `/__w/<workspaceId>` 返回 404；
- verified 企业 Host 可以访问自己的 Workspace；
- A 企业 Host 不能访问 B 企业 Workspace；
- 生产配置存在 `NEXT_PUBLIC_APP_URL` 时仍检查请求 Host；
- canonical 指向真实企业域名；
- 普通成员不能读取全部员工名片。

## 20.6 D4

- 空 `workspaceId` 不触发数据库 UUID 错误；
- 同一幂等 key 不重复扣额度；
- 企业员工个人为 free 时仍可使用企业授权 AI；
- confirm 和 refund 并发只产生一个合法最终结果；
- 退款失败时不显示“已退回”；
- confirm 失败不返回普通成功；
- 全部新测试断言与结构化返回值一致。
